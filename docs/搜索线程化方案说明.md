# 为什么「搜索/意图」档 AI 不做 worker 线程化（方案 B），改走主线程协作让帧（方案 A）

> 日期：2026-09-20 · 关联：`docs/开发日志.md` / `t_mech_bridge_quiet` 护栏
> 结论一句话：**B 在 GDScript 内核下不可行（会段错误）；A 用主线程协作让帧，无冻结、无崩溃、确定性不变，客户端+服务器都安全。**

---

## 一、问题背景

「搜索/意图」档 = `MechBridge`，用 **alpha-beta（`search_best`）递归搜索**：每个节点 `_drive_to_round_end` 把**整回合其余席位 + E 阶段全部模拟一遍**，叶估值用 `MechValue` 拟合。它原本在调用方**主线程一把同步跑完** → 一次 `ask` 占满一帧（数 10~100ms+ 纯算力）→ 每回合逐细胞决策**顿卡**。想仿 MC/MCTS 把重算抛给 worker `Thread`。

## 二、为什么方案 B（worker 线程化）走不通

**实测铁证（探针已删，结论可复现）：**

| 场景 | worker Thread | 结果 |
|---|---|---|
| MC/MCTS（扁平 rollout，预算封顶） | 生产在用 | ✅ 不崩 |
| `best_by`（非搜索）· 2人局 | `t_mech_bridge_quiet` 只测到这条 | ✅ 不崩 |
| `best_by` · 4人局 | 探针实测 | 💥 **段错误** |
| `search_best`(alpha-beta) · 2人局 | 探针实测 | 💥 **段错误** `Nonexistent function 'solidify_threshold' in base 'GDScript'` |
| `search_best`(alpha-beta) · 4人局 | 探针实测 | 💥 **段错误** `Nonexistent function '' in base 'MechIntent/CWGame/Callable'` |

**逐项排除，锁定真因：**
- **不是静态解析问题**：在 worker 里 `MechValue.*`/`MechBridge.*`/`CWEval.*` 的 `has_method`/构建 Callable **全部 ok**。
- **不是全局人数问题**：2人局 search 也崩。
- **不是"搜索 vs 非搜索"本身**：4人局 `best_by` 也崩。
- **真因 = Godot 4.5.2 `Thread` 里跑"深/高量 `await` 协程"不稳**：alpha-beta 递归（`_ab_line` 套 `_ab_line`）+ 每节点整回合前推（`_drive_to_round_end` 里几十次 `await g.step`），协程函数栈深、无预算勒停。而 MC/MCTS worker 是**扁平 loop + 预算封顶**，协程量低，能抗线程。高量协程在裸 `Thread` 执行 → GDScript 协程态损坏 → 报「Nonexistent function '' / Invalid property ''」（损坏后的假象）→ **段错误**。

**修好 B 的代价**：要么把搜索改写成扁平迭代 + 预算封顶（像 MC）——等于重写 AI 搜索、改变行为；要么改 Godot 引擎协程机制——不可控。工程上不可行/代价过高。

## 三、什么情况下走不了 B

走不了 B 的充分条件（满足其一即不可行）：
1. **GDScript 内核 + 裸 worker `Thread`** 上跑**递归 / 高量 `await` 协程**搜索（如 alpha-beta + 整回合前推）→ 段错误。
2. 只有当搜索是**扁平、预算封顶、浅协程**（如 MC/MCTS）时，worker 线程才安全。
3. **C# 纯同步内核**（仓库 `core/CellWar.Core`）能根治：规则层**纯 C# 同步**、演出是**数据回传**（`Stage.Emit` 收集进返回值）、RNG 显式传参，只有宿主输入边界（`ISession.RequestAsync` 问真人玩家）才 async → 搜索抛 .NET `Task` 是普通并行，**没有 GDScript 协程态可损坏**。**但 AI 搜索（`mech_intent`/`MechValue`）还没移植到 C#**，且线上仍是 GDScript，所以当前不可依赖。

## 四、为什么走方案 A（主线程 + 协作让帧）

- **搜索本质已是"零真挂起纯算"**：image `sim_quiet` 下 `world.*`（`revive/e_phase/round_start/enter_tile`）全跳过演出、同步算完，`await` 是引擎 API 的协程**外壳**，从不真等。
- **A = 搜索仍在主线程跑，但在重循环里周期 `await process_frame` 让出一帧** → 渲染/输入照转 → **不冻结**；零线程 → 零协程坑 → **不段错误**；AI 强度**不变**；**确定性不变**（答案只依赖 rng/局面，与帧数无关，`t_mech_bridge_quiet` 锁死 a 同步==a 协作）。
- 单机客户端**和**服务器都安全（服务器照常同步跑，只是每帧能继续轮询其它连接/房间）。
- 改动**收敛**在搜索循环插让步 + 移除线程，不重写 AI。

## 五、当前方案已改成 A

1. **`mech_intent.gd`**：加 `coop_every` + `_coop_step()`（每 48 步让一帧），插入 `evaluate_path` / `_play_path` / `_drive_to_round_end` 的重循环。
2. **`mech_bridge.gd`**：**删除 worker Thread**（`_threaded_pick`/`cw_mech_thread_entry`）；`use_threading=true` 语义改为「主线程协作让帧」；`cw_mech_work` 依 `cfg.use_threading` 打开 `intent.coop_every=48`。
3. **`match.gd`**：单机「搜索/意图」档打开协作让帧。
4. **`cw_net_bridge.gd`**：服务器专家 `mc` 保持 `use_threading=true`（现在=协作让帧，改服务器不冻结）。
5. **`headless_test.gd`**：`t_mech_bridge_quiet` 补**四人局搜索 · 协作让帧护栏**——同局面协作让帧再问一次，断言不崩、答案合法、与同步一致。

**验证**：`t_mech_bridge_quiet` 13/13 通过（含新护栏：4人局协作让帧不崩、答案与同步 7==7）；非网络回归 61 项检查全绿。网络测试在本机 headless 下仍环境性不便跑（属另一码事，且不再段错误），需在有网络运行条件的机器复跑。

---

## 附：一句话版本

**B 要"大改"是因为递归 alpha-beta + 整回合前推的深 `await` 协程是 GDScript 运行时约束的雷区——worker `Thread` 一踩就段错误（MC/MCTS 扁平+封顶所以没事，C# 同步内核天生没这坑）；所以改走 A：搜索留在主线程、重循环周期让帧，不冻结、不崩、确定性不变。**
