## 〇、三条总规矩 + 编码约定

1. **零浮点**：能量、固化计数、储量、费用、收入一律**十分位整数**（`30` = 3.0 能量）。百分比是整数百分点；千分比（`solid_fraction` / `store_fraction` / `proliferate_chance`）是整数千分点。协议里**不出现** JSON 小数。
2. **零 rng**：协议里不存在 rng 字段。rng 只走 `save()`（宿主专用，绝不过网、绝不裁剪）。
3. **未知字段 = 硬错**：消费者收到本文没列的键必须报错（`CWMirror` 与 C# 解码器各一条测试）。**缺失字段**只在一种情况下合法：tier B 派生量，且 envelope 的 `produced_tiers` 没有 `"B"`。

编码约定（两侧生产者逐条对齐，跨生产者对拍靠它）：

| 类型 | JSON 形状 | 备注 |
|---|---|---|
| 坐标 | `{"q": int, "r": int}` | GD `Vector2i(x, y)` = `(q, r)`；「没有坐标」用 `null`（不用 `Vector2i.MAX` / `Vector2i.ZERO` 之类哨兵） |
| 布尔 | `true` / `false` | 语义键**字符串里**仍是 `1` / `0`（`cw_semkey.gd` 文法不变） |
| 枚举 | **GD 的整数值** | `Faction` 0/1、`Tissue` 0/1/2、`Special` 0..3、`ImmuneType` 0..4、`CancerType` 0..3、`immune_level` 0..3。C# 生产者按附录 A 换算，**不把 C# 枚举值漏出去** |
| 细胞引用 | **cell id**（`state.cells[]` 的下标，从 0 起） | 不是席位。C# `EntityId` 从 1 起，`id = EntityId − 1`；席位 = `players[pid].cell_id` 反查 |
| 字符串 | UTF-8 原文 | 卡名、技能名、文案都是中文原文；`label` / `prompt` / `detail` 由内核给（拍板 9） |
| 字典 | 键序无关 | 对拍前两侧各自按键排序再比 |
| 数组 | **有序** | 本文每个数组都写明序；没写的就是「引擎原序」 |

## 一、Envelope

```jsonc
{
  "p": 3,                          // 协议版本；字段增删改名一律升号；消费者 p 不等就拒（p=3：2026-09-19 删七个世界事件残留字段，见 §九）
  "ruleset": { "host_abi": 1, "rules_build": "core-slice-1+b0", "digest": "sha256:…" },
  "rev": 1837,                     // 生产者内部修订号（C# Revision / GD 每次 snapshot 自增），只用于排序与去重
  "obs_seq": 412,                  // 这份观测反映「第 obs_seq 条演出 / 日志条目之后」的状态（= 内核句柄条目 seq 的水位）
  "viewer": 2,                     // >= 0 席位 / -1 观众 / -2 全知（禁止过网）
  "open_hands": false,             // 仅 viewer = -1 有意义，= cw_room.gd 的 watch_hands
  "produced_tiers": ["A"],         // GD 生产者恒 ["A", "B"]；C# 批 0 恒 ["A"]
  "full": true,                    // v1 恒 true
  "base": null,                    // 增量留位，v1 恒 null
  "state": { "board": {…}, "cells": […], "g": {…} },
  "ask": { … } | null,
  "logs": { "from": 412, "lines": ["…"] }
}
```

* `ruleset` 三个字段**必须分开**（迁移计划 §三 硬不变量③）：`host_abi` 是握手闸；`rules_build` 与 `digest` 只上报、不闸。`digest` = 规则内核对 `tune` 全量 + 卡表的 sha256（GD：`CWTuning.signature()` 的口径；C# 批 0 先填 `rules_build` 同值，sidecar 那一批定稿）。
* `obs_seq` 与 `rev` 都不进状态哈希，也不参与对拍（两侧计数口径不同）。
* **增量不实现**：`base` 留位。体积在步 10 实测后填进附录 D。

## 附录 C · sidecar 传输草案（sidecar 那一批定稿；这里只钉与协议相关的部分）

* **JSON Lines over stdio**（一行一报文，UTF-8，无 BOM）。宿主 → 内核是请求 `{"id": n, "op": "...", ...}`，内核 → 宿主是应答 `{"id": n, "ok": true, "result": …}` 或推送 `{"push": "entry", "entry": {…}}`。
* `op` 与 `CWKernel` 方法**一一对应**（`open / close / abort / version / caps / observe / logs_for / pull / ack / answer / abort_ask / can_save / save / restore / replay_tape / pending / step / log_msg / surrender / state_hash / query / fork_for_rollout`）。`observe` 的 `result` 就是本文的 envelope；`pull` 的 `result` 是附录 B 的条目数组。
* 首行握手：内核起来先推 `{"push": "hello", "host_abi": 1, "rules_build": "...", "digest": "..."}`；宿主只闸 `host_abi`（硬不变量③），8 秒没等到 = `HANDSHAKE_TIMEOUT`。**握手失败 / 起不来绝不计进 `patch_state.gd` 的 `STRIKES`**（硬不变量②）。
* 数字一律整数（本文规矩 1）；坐标 `{q, r}`；没有 rng。
* `save` 的 blob 只在宿主进程与内核进程之间走管道，**不进 envelope、不过网**。
