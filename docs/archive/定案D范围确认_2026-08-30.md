## 三、实测数据

全部在引擎里实跑取证，探针脚本跑完即删。

### 点名的那处

```
巡航闸门烧 / 驻留闸门烧        true / false    ← 驻留的额度留住了
```

### 顺手带上①：CXCR3趋化 价钱已到下限

X 级基准 0.5，【组织浸润】先减 0.3 已踩到 `MOVE_CUT_MIN`，CXCR3 再减也减不动：

```
报价                    0.2
CXCR3 剩余次数           2        ← 旧版会变 1
```

### 顺手带上②：LFA-1黏附 价钱已到下限

```
报价                    0.2
LFA-1 闸门是否已烧        false    ← 旧版 true
```

### 顺手带上③：炎症趋化 遇上价钱正好已经是 0.5

I 级基准 1.0 → 先打【CXCR3趋化】压到 0.5 → 再打【炎症趋化】「改为 0.5」，改不动：

```
基准价                                  1.0
报价（CXCR3 压到 0.5，炎症趋化改不动）        0.5
CXCR3 剩余次数（它确实减了钱，照常消耗）        1
炎症趋化 条目还在                          true     ← 旧版会被吃掉
```

⚠ 这条和**定案 A 是同一张卡的两面**：价钱低于 0.5 时它**抬价**（A 说保留抬价），
价钱正好等于 0.5 时它**什么也没干**（D 说别消耗）。两条定案在这张卡上会同时生效。

### 顺手带上④：上皮—间质转化 遇上伪足穿透

黑色素瘤【伪足穿透】把基准价压到 0.2，EMT 的「改为 0.2」改不动：

```
dest 邻接癌性组织数        2
基准价                   0.2      ← 伪足穿透生效
报价（改为 0.2 = 没变）     0.2
EMT 剩余次数              3        ← 旧版会变 2
```

### 顺手带上⑤：迁移激活 在价钱已经是 0 时

```
迁移激活额度还在           true     ← 旧版会被吃掉
```

**这条是里面最粗的一个**：旧代码的 `consume_free_move` 在 `_do_move` 开头
**无条件调用**，只要事件在场，免疫细胞每次移动都消耗掉那份额度，
哪怕这一次是靠【组织巡航】免费的、跟迁移激活半点关系没有。

## 四、我为什么扩大了范围

**① 只修点名的两张会留下同类不一致。** 同样是「有限资源被白烧、玩家从报价上
完全看不出来」，很难解释凭什么组织驻留该省、CXCR3 不该省。这条不一致下次审查
我还得再报一遍。

**② 开特例要维护一张豁免名单，而那正是问题 6 的成因。** 旧版「报价」和「收费」
是分开写的两份谓词，靠一句注释要求「必须一字不差」，问题 6 就长在那条缝里。
若按卡开特例，等于在合并后的函数里重新引入一张要人工保持同步的表。

**③ 通用判据只有一行。** 实现就是 `if after == cost: return cost`——
「没改变数值就等于没结算」，不需要任何卡名列表。

## 五、代价（必须讲清楚）

**（甲案的代价，已随选定乙案而消解，保留作为当时的判断依据）**

甲案是一次全面倒向玩家的削弱：移动费相关的所有限次资源都变得更耐用，
会让【CXCR3趋化】【上皮—间质转化】这类卡的**实际可用次数变多**，
【迁移激活】的价值也上升，而**平衡影响没有测过**。

选定乙案后这一层担忧基本没有了：只有「本来就免费的那一步」不再白烧额度，
折扣卡的实际次数与旧版完全一致。唯一的净变化是
【组织巡航】+【组织驻留】同装时每回合多一次免费移动，以及【迁移激活】
不再被无关的免费移动吃掉——两者都是原本就该有的行为。

把判据从「所有卡」缩成只管**「变 0」类**（组织巡航首移、组织驻留、迁移激活），
恢复 ①③④ 的旧行为——也就是说：**免费额度省，限次折扣不省。**

改动在 `cw_actions._apply_move_card` 里给 `spend` 加个条件，五行以内；

## 七、请拍板

| 选项 | 含义 | 我的意见 |
|---|---|---|
| 甲 | 维持通用判据：所有没起作用的移动费卡都不消耗 | 当时推荐 |
| **乙** | 收窄成只管免费额度：①②③④ 恢复旧行为 | ✅ **Kevin 选定** |

**⑤（迁移激活）保留新行为**——它本身就是「免费额度」，落在乙案的范围内。
旧版那个无条件消耗更像单纯的疏漏（`consume_free_move` 压根没判断这次移动
是不是靠它才免费的），不像是设计。

### 实装要点（乙案落地时踩到的）

必须分清**两件事**，不能合成一个判据：

| | 含义 | 裁定 |
|---|---|---|
| **「适不适用」** | 目的地对不对、次数还有没有 | 为假 → **一律不消耗** |
| **「有没有改到钱」** | 适用了，但价钱没变 | 只对**免费额度**有意义；限次折扣照扣 |

合成一个判据的话，「打出【炎症趋化】却往健康组织走」和「打出【炎症趋化】但价钱
本来就是 0.5」会被当成同一件事——而团队对这两者的裁定是**相反的**。
代码里因此有 `applies` 与 `free` 两个标志，测试 D-2b 专门钉住这一点。

限次折扣白花一次时会打一句日志「本次未改变费用，次数仍消耗」——
不省是团队的决定，但玩家有权知道自己刚少了一次。
