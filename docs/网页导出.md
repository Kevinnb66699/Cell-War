# 网页版（Web / WASM）

2026-09-14 起。Kevin：**不专门做安卓版了，改做网页版。** 安卓那条线的记录留在
`docs/安卓导出.md`，没删（预设和脚本都还在，`use_gradle_build` 已改回 `false`，
拿现有 SDK 还能出探路包）。

## 为什么网页比安卓顺

三件在安卓上要命的事，在网页上**天然不是问题**：

| | 安卓 | 网页 |
|---|---|---|
| 明文 HTTP | 9 起默认禁，必须开 Gradle 自定义构建塞 `network_security_config` | ⚠ **也不行，见下** —— Godot 网页版要求安全上下文（HTTPS） |
| 联机传输 | 要 WebSocket —— 幸好本来就是 | 同左，`WebSocketPeer` 直接能用 |
| 悬停 | 触屏没有悬停，整套详情 UI 读不出来 | **桌面浏览器有鼠标悬停，原样可用** |

代价是手机浏览器仍然没有悬停 —— 但那是「手机适配」这一件事，不再和「能不能跑」捆在一起。

### 预设里最要紧的两句

`game/export_presets.cfg` 的 `[preset.3] Web`：

* **`variant/thread_support=false`** —— 开线程的 web 包要求浏览器处于**跨源隔离**状态
  （COOP/COEP 两个响应头）。先关着，等 HTTPS 就位、且确认要不要更强的 AI 时再说：
  打开它只需要 nginx 多发两个头 + 换 `web_*`（带线程）模板重导一次。
  ⚠ **别把它和「要不要 HTTPS」搞混** —— 下面那条说明了，不开线程**照样**必须 HTTPS。
* **`script_export_mode=0`** —— 同另外三个预设。网页用不上热更，但护栏
  （`headless_test` 那条）按「每个预设都是 0」核，保持一致。

### 渲染器不一样

网页只有 **Compatibility** 渲染器（桌面是 `forward_plus`）。已验证棋盘、演出层、
`store_progress.gdshader` 都画得对。以后写 shader 要记得这条路也得过。

## ⛔ 2026-09-14 部署时撞到的硬墙：Godot 网页版**必须** HTTPS

包传到服务器、用公网地址 `http://124.221.78.13/cellwar/web/` 打开，Godot 的加载器直接拒绝启动：

```
Error
The following features required to run Godot projects on the Web are missing:
Secure Context - Check web server configuration (use HTTPS)
```

**之前在本地 `http://127.0.0.1:8099` 能跑，是因为 localhost 本身就算安全上下文** ——
那一轮验证没能暴露这条。换成公网 IP 的明文 HTTP 就现形了。

⚠ 所以**「关掉线程就能走普通 HTTP」是错的**：`thread_support` 决定的是要不要**跨源隔离**
（COOP/COEP），而安全上下文（HTTPS）是 Godot 网页版**无条件**的前提，两码事。

### 服务器现状（查出来的）

* `/cellwar/` 由 `server_name 124.221.78.13` 那个 80 端口的 server 块提供，
  `alias /var/www/cellwar/`。网页版已经传到 `/var/www/cellwar/web/`（38 MB），
  MIME 也修好了（nginx 的 `mime.types` 里原本**没有 wasm**，已补一行
  `application/wasm wasm;`，备份在 `/etc/nginx/mime.types.bak-cellwar`）。
  **HTTPS 一就位，这份文件原地就能用。**
* 这台机器上另有两个域名站：`book.jiling.chat` / `hosp.jiling.chat`，各有独立证书
  （**不是泛域名**），而且**两张都已经过期**（7/13 和 8/2 到期）。
  它们又把 HTTP 强制 301 到 HTTPS，所以那两个站眼下对外是打不开的。
* **域名走 80 端口是通的**（`http://book.jiling.chat/` 从外面打返回 301），
  所以 ACME 的 HTTP-01 验证能做 —— 签一张有效证书这条路是通的。
* `hosp.jiling.chat` 已经在做 `location /api/ws` 的反向代理，
  **说明这台 nginx 上 wss 反代是现成可抄的。**

### 于是接下来要定的事

1. **用哪个主机名**：新开一个（比如 `cellwar.jiling.chat`，要加 DNS A 记录）
   还是挂在现有某个站底下。两张证书都不是泛域名，新子域要单签。
2. **联机必须跟着走 wss**：HTTPS 页面连 `ws://124.221.78.13:8611` 会被当混合内容拦掉。
   照 `hosp` 那个 `/api/ws` 的写法反代到 `127.0.0.1:8611` 即可，
   但客户端那边连的地址要跟着改（`online_panel.gd` 现在是拼 `ws://` + 地址）。

## 还没解决的（按要紧程度排）

### ① 热更在网页上既没用又有害 —— 每次加载白等 10 秒

`boot.gd` 一启动就去取 `http://124.221.78.13/cellwar/latest.json`。从网页发是**跨源请求**，
浏览器直接拦：

```
Access to fetch at 'http://124.221.78.13/cellwar/latest.json?t=...' from origin
'http://127.0.0.1:8099' has been blocked by CORS policy
```

于是每次打开都卡在「正在检查更新」，等满 `CHECK_BUDGET`（10 秒）才自己进游戏。
（6 秒时会露出「跳过」按钮，所以不是卡死。）

**而网页版根本不需要热更** —— 重新部署一份静态文件就是更新。

修法是 `boot.gd` 里加一句 `if OS.has_feature("web"): 直接进游戏`。
⚠ **但改 `boot.gd` 会让桌面端的补丁打包器整个拒绝出包**（启动器在挂载补丁之前就读了它，
见 `build_patch.gd` 的闸），到下次全量发版为止。所以**这一条要和一次全量发版一起做**，
不能顺手改。

把网页放到 `124.221.78.13` 上之后变成同源，CORS 就没了 —— 但 10 秒那件事只是从
「被拦」变成「真去查了一遍」，仍然没意义。该跳过还是要跳过。

### ② 强 AI 走线程，单线程网页上没验过

`mcts_bridge.gd` / `monte_carlo_bridge.gd` 的写法是：

```gdscript
t.start(...)
while not 结果出来了:
    await tree.process_frame     # 主线程出帧等结果
t.wait_to_finish()
```

无线程的 web 构建上，如果 `Thread.start()` 不是同步执行那个 callable，
这个循环就会**永远等下去**（表现是 AI 再也不出手，而不是报错）。

首次实测用的是 **AI 强度「普通」**，那一档不走线程（`match.gd`：
`thinking = level != AI_NORMAL`），所以这条**没被验到**。

建议无论如何加一道判据 —— 两边都对、且不依赖 Godot 的回退行为：

```gdscript
if not OS.has_feature("threads"):
    return await _eval_sync(snap, options, cfg)
```

`_eval_sync` 本来就存在（拿不到 SceneTree 时的退路）。代价是强 AI 思考时标签页会卡住，
那是单线程的必然，另说。

### ③ 联机：页面必须用 http:// 提供

客户端连的是 `ws://124.221.78.13:8611`。**https 页面连 `ws://` 会被当混合内容拦掉**，
所以网页版必须走 `http://`。我们本来就上不了 HTTPS，两边自洽 —— 但这条要写死在流程里，
哪天有人给页面套了 HTTPS，联机会当场全断。

### ④ 反馈口要同源

`feedback.gd` POST 到 `http://124.221.78.13/cellwar/feedback`。网页放在同一台机器上就是
同源、没问题；放别处就要给那个接口加 CORS 头。

### ⑤ 存档 / 设置 / 回放存在 IndexedDB

`user://` 在网页上是 IndexedDB。玩家清站点数据就全没了，且换浏览器不通用。

### ⑥ 没验过的

* **音频**：浏览器要求用户手势之后才能出声。点击音效大概率没问题（点了才响），
  但没实测。
* **首次加载 39 MB**：国内服务器直连，没测过真实速度。
* **手机浏览器**：悬停的问题原样存在（见 `docs/安卓导出.md` 那条），另外还有
  横屏、安全区、虚拟键盘。
