# 网页版（Web / WASM）

2026-09-14 起。Kevin：**不专门做安卓版了，改做网页版。** 安卓那条线的记录留在
`docs/安卓导出.md`，没删（预设和脚本都还在，`use_gradle_build` 已改回 `false`，
拿现有 SDK 还能出探路包）。

## 为什么网页比安卓顺

三件在安卓上要命的事，在网页上**天然不是问题**：

| | 安卓 | 网页 |
|---|---|---|
| 明文 HTTP | 9 起默认禁，必须开 Gradle 自定义构建塞 `network_security_config` | ⚠ **也不行，见下** —— Godot 网页版要求安全上下文（HTTPS） |
| 联机传输 | 要 WebSocket —— 幸好本来就是 | 同左，`WebSocketPeer` 直接能用 |
| 悬停 | 触屏没有悬停，整套详情 UI 读不出来 | **桌面浏览器有鼠标悬停，原样可用** |

代价是手机浏览器仍然没有悬停 —— 但那是「手机适配」这一件事，不再和「能不能跑」捆在一起。

### 预设里最要紧的两句

`game/export_presets.cfg` 的 `[preset.3] Web`：

* **`variant/thread_support=false`** —— 开线程的 web 包要求浏览器处于**跨源隔离**状态
  （COOP/COEP 两个响应头）。先关着，等 HTTPS 就位、且确认要不要更强的 AI 时再说：
  打开它只需要 nginx 多发两个头 + 换 `web_*`（带线程）模板重导一次。
  ⚠ **别把它和「要不要 HTTPS」搞混** —— 下面那条说明了，不开线程**照样**必须 HTTPS。
* **`script_export_mode=0`** —— 同另外三个预设。网页用不上热更，但护栏
  （`headless_test` 那条）按「每个预设都是 0」核，保持一致。

### 渲染器不一样

网页只有 **Compatibility** 渲染器（桌面是 `forward_plus`）。已验证棋盘、演出层、
`store_progress.gdshader` 都画得对。以后写 shader 要记得这条路也得过。

## ⛔ 2026-09-14 部署时撞到的硬墙：Godot 网页版**必须** HTTPS

包传到服务器、用公网地址 `http://124.221.78.13/cellwar/web/` 打开，Godot 的加载器直接拒绝启动：

```
Error
The following features required to run Godot projects on the Web are missing:
Secure Context - Check web server configuration (use HTTPS)
```

**之前在本地 `http://127.0.0.1:8099` 能跑，是因为 localhost 本身就算安全上下文** ——
那一轮验证没能暴露这条。换成公网 IP 的明文 HTTP 就现形了。

⚠ 所以**「关掉线程就能走普通 HTTP」是错的**：`thread_support` 决定的是要不要**跨源隔离**
（COOP/COEP），而安全上下文（HTTPS）是 Godot 网页版**无条件**的前提，两码事。

### 已上线（2026-09-14）

**https://cellwar.jiling.chat/**

| | |
|---|---|
| 证书 | Let's Encrypt，certbot 签的，2026-12-14 到期，**自动续期已配**（`certbot renew --dry-run` 过） |
| 站点配置 | `/etc/nginx/sites-available/cellwar.conf`（certbot 加的 443 块 + 80 跳转） |
| 根目录 | `/var/www/cellwar/web`（和老的 `http://124.221.78.13/cellwar/web/` 是同一份文件，但那个地址**跑不起来**——没有安全上下文） |
| 联机 | `location /ws` 反代到 `127.0.0.1:8611`，超时 1 小时（默认 60 秒会掐掉打到一半没人操作的连接） |
| 压缩 | `gzip_static on` + 部署时预压。**wasm 38 MB → 9.26 MB**，四倍 |
| MIME | nginx 的 `mime.types` 原本**没有 wasm**，已补一行（备份 `mime.types.bak-cellwar`） |

出包 + 上传 + 核对都收进了 `tools/deploy_web.sh`：

```bash
tools/deploy_web.sh              # 导 release、预压、上传、核对
DEBUG=1 tools/deploy_web.sh      # 导 debug（报错信息全）
DRY=1   tools/deploy_web.sh      # 只导不传
```

脚本里写死了三个踩过的坑：① Godot 导出失败时**退出码仍是 0**，所以既抓输出里的 ERROR
也核产物；② wasm 的 MIME 必须是 `application/wasm`；③ **核对必须按域名 + HTTPS 打** ——
同一份文件被两个 server 块同时 alias 着，打错主机名的话压缩那一条会永远误报「没生效」
（第一版就是这么误报的）。

## 还没解决的（按要紧程度排）

### ① 「不安全」与 10 秒白等 —— 已在**发版侧**修掉，没动客户端（2026-09-15）

上线当天 Kevin 第一句是「为什么 cellwar 显示不安全，其它两个都安全」。不是证书问题
（`ssl_verify=0`），是我们自己的代码：`boot.gd` 的热更 manifest 和 `feedback.gd` 的反馈口
都写死成 `http://124.221.78.13/cellwar/`，HTTPS 页面上这叫**混合内容**，浏览器直接拦掉
并给整页打标；拦掉之后还要等满 `CHECK_BUDGET`（10 秒）才进游戏。

改那两个地址要动 `boot.gd` —— 而**它在挂载补丁之前就被读了、热更不了**，动它就必须全量发版，
且从那一刻起到发版为止桌面端的补丁打包器会整个拒绝出包。Kevin 问「能不能不动客户端、
只动网页端的发版」。**能**：那两处地址是**运行时用 fetch 发出去的**，而 `index.html`
是我们在部署时自己生成的。

两半：

**① `tools/web/same_origin_shim.js`** —— `deploy_web.sh` 在打包后把它注入 `index.html` 的
`<head>`（**必须在引擎脚本之前**）。它包住 `fetch` 与 `XMLHttpRequest.open`，
把 `http://124.221.78.13/cellwar/…` 改写成同源相对路径 `/cellwar/…`。

**② nginx 在 `cellwar.jiling.chat` 块上接住这两条**：

* `/cellwar/latest.json`（含 `.sig`）→ **故意 404**。网页版不需要热更（重新部署静态文件
  就是更新），而且让它装桌面补丁反而危险 —— 补丁按桌面基线打，可能把网页包里更新的脚本
  盖回旧的。取不到 manifest，`boot.gd` 就当「没有更新」**立刻**进游戏，10 秒预算也省了。
* `/cellwar/feedback` → 代理到本机 8612。这条不只是消警告：**网页版的反馈本来是发不出去的**
  （被混合内容拦着），现在能用了（实测 POST 返回 200）。

实测：控制台**一条 Mixed Content 都没有**，页面直接进主菜单。

⚠ **这是发版侧的猴补丁，不是根治。** 它赌的是 Godot 的 web 版 HTTPRequest 走 fetch/XHR
（4.5 是这样）。哪天引擎换了实现，它会**静默失效** —— 页面又变回「不安全」。
正经的修法仍然是改 `boot.gd` 的 `SELF_HOST`，随下一次全量发版做掉，然后删掉那个 shim。

### ② 强 AI 的线程判据（已加，2026-09-14）

`mcts_bridge.gd` / `monte_carlo_bridge.gd` 的 `_threaded_eval` 本来是
「起线程 → 每帧轮询 holder → `wait_to_finish`」。无线程的 web 构建上，如果
`Thread.start()` 不同步执行那个 callable，这个循环会**永远等下去** ——
表现是 AI 再也不出手，而且**不报任何错**。

**已加判据**（两个桥各一份）：

```gdscript
if not OS.has_feature("threads"):
    return await _eval_sync(snap, options, cfg)
```

`_eval_sync` 本来就存在（拿不到 SceneTree 时的退路）。代价是强 AI 思考时标签页会卡住，
那是单线程的必然。

⚠ **这条只能按源码核**：桌面跑测试时 `has_feature("threads")` 恒为真、判据永远不进，
而真会出事的构建跑不了那套无头测试。所以 `t_ai_mc` 开头是一条**源码断言**。

⚠ 首次实测用的是 AI「普通」档，那一档本来就不走线程（`match.gd`：
`thinking = level != AI_NORMAL`），所以**「强 AI 在网页上到底跑不跑得动」仍然没被实测过**，
只是不会再静默死等了。

### ③ 联机默认地址已按平台分开（已改，2026-09-14）

`CWSettings.server` 的默认值现在按 `OS.has_feature("web")` 分两档：

* **网页版** → `CWNet.WEB_HOST` = `wss://cellwar.jiling.chat/ws`。
  必须是 `wss://` —— HTTPS 页面连 `ws://` 会被当混合内容直接拦掉，没有第二条路。
* **桌面版** → 照旧 `ws://124.221.78.13:8611`。少一层 TLS 和反代，
  而且**不受证书死活影响**：这台机器上的证书历史上过期过好几次，
  没必要让桌面联机也跟着一起挂。

`online_panel.gd` 本来就认 `ws://` / `wss://` 前缀，玩家手填别的地址照常可用。

**已实测连通**（2026-09-14）：浏览器里打开 → 联机对战 → 进入大厅，
拿到「暂无公开房间」的大厅页，能建房。服务端那边直连 8611 和经 nginx 的
wss 握手都返回 `101 Switching Protocols`。

⚠ **但上线当天 Kevin 报「网页端连不上服务器」，原因不在服务端** ——
`CWSettings.load_prefs()` 里那一句 `server = cfg.get_value("online", "server", server)`：
**存下来的地址会盖掉新默认值**。他先前开过页面、存下的是 `124.221.78.13:8611`，
新包的 `wss://` 默认值根本轮不到生效，于是每次都去连一个必然被混合内容拦掉的 `ws://`。
玩家看到的是「连不上服务器」，而真因藏在浏览器的存储里，谁也查不到。

修法三处（2026-09-14）：
1. 平台默认地址抽成 `CWSettings.default_server()` —— 有三个地方要用同一个答案
   （默认值、读盘作废判定、面板上的「默认」按钮），各写一份必漂；
2. **读盘时把网页上存下来的非 `wss://` 地址直接作废**，回落到默认值 —— 它在网页上
   本来就不可能工作，留着只会制造查不出来的故障；
3. 面板上的「默认」按钮改用 `default_server()`，原来硬写桌面那套地址。

### ④ 反馈口要同源

`feedback.gd` POST 到 `http://124.221.78.13/cellwar/feedback`。网页放在同一台机器上就是
同源、没问题；放别处就要给那个接口加 CORS 头。

### ⑤ 存档 / 设置 / 回放存在 IndexedDB

`user://` 在网页上是 IndexedDB。玩家清站点数据就全没了，且换浏览器不通用。
