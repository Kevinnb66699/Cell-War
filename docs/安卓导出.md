# 安卓导出（探路阶段）

2026-09-14 起。目标先定成一句话：**出一个能装、能进主菜单、能打单机的 APK**，
看真机上排版和性能什么样。触摸操作的改造、上架那套，都不在这一阶段。

## 这台机器上还缺什么

已经齐的三样（查过，不是假设）：

| | 状态 |
|---|---|
| Godot 4.5 安卓导出模板 | ✅ `%APPDATA%/Godot/export_templates/4.5.stable/` 里 `android_debug.apk` / `android_release.apk` / `android_source.zip` 都在 |
| 调试签名 keystore | ✅ `%APPDATA%/Godot/keystores/debug.keystore`（编辑器设置指着它，口令 `android`） |
| JDK | ✅ Microsoft OpenJDK 25，`JAVA_HOME` 已设 |

缺的只有一样：

| | 状态 |
|---|---|
| **Android SDK** | ❌ 完全没有。编辑器设置里 `export/android/android_sdk_path` 指着 `C:\Users\fanke\AppData\Local\Android\Sdk`，那个目录不存在 |

**装到编辑器设置已经指着的那个路径**，Godot 就不用再改设置：

```
C:\Users\fanke\AppData\Local\Android\Sdk
```

### 第一阶段（出探路包，不走 Gradle）

Godot 用**预编译模板**导出时，只从 SDK 里拿两样：`platform-tools/adb` 和
`build-tools/<版本>/apksigner`（给 APK 签名）。所以最小集就够：

- `platform-tools`
- `build-tools;35.0.0`

约 70 MB（外加 commandlinetools 本体约 130 MB）。用 Android Studio 的 SDK Manager 装也一样。

⚠ **这一档出来的包收不到热更**：安卓 9 起默认禁明文 HTTP，而 manifest / 补丁包 / 反馈口
都在 `http://124.221.78.13/cellwar/`。**不会报错，是静默失败**。其余（启动、主菜单、单机对局、
排版、性能）都能验。

### 第二阶段（热更也要通 → 必须开 Gradle 自定义构建）

**查过了：Godot 4.5 的安卓导出预设里没有任何 cleartext / network_security_config 开关**
（在引擎二进制里搜过，只有 `permissions/custom_permissions` 和 `gradle_build/*`）。
所以 2026-09-14 拍板的「只给 `124.221.78.13` 这一个主机开明文例外」**只能走 Gradle 自定义构建** ——
把 `res/xml/network_security_config.xml` 放进 `android/build/`，再让清单引用它。

版本要求**从模板自己的 `config.gradle` 读出来的**，不是凭印象：

```
androidGradlePlugin 8.6.1     compileSdk 35     targetSdk 35     minSdk 24
buildTools 35.0.0             Gradle 8.11.1     javaVersion VERSION_17
```

于是第二阶段还要补：

- `platforms;android-35`
- **JDK 17** —— 和现有的 JDK 25 并存即可，把 Godot 编辑器设置里的
  `export/android/java_sdk_path` 指向 17 那个。Gradle 明确要 `JavaVersion.VERSION_17`，
  拿 25 去跑 AGP 8.6.1 大概率起不来。
- 首次构建 Gradle 包装器会自己下 Gradle 8.11.1（约 130 MB）

NDK 一般**不用**装（原生库是导出模板自带的）；万一 Gradle 报缺，版本是 `28.1.13356709`。

## 仓库里已经准备好的部分

- `game/export_presets.cfg` 多了一个 `[preset.2] Android`，`gradle_build/use_gradle_build=false`
  （第二阶段改成 `true`），包名暂定 `com.springsense.cellwar` —— **这个名字是我随手起的，
  正式发布前要定**（装过之后再改包名，手机上会变成两个独立的 app）。
- **`script_export_mode=0` 显式写进了新预设**。Godot 4.5 新建预设默认是 `2`（压缩二进制 token），
  那会让包里根本没有 `.gd`、只有 `.gdc` + `.remap`，补丁塞进去的纯文本 `.gd` 没人看 ——
  **每个补丁都变成哑弹**。2026-09-02 到 09-10 真这么白发了一串补丁，护栏在 `headless_test` 里。
  安卓这条线漏掉这一句，等于把同一个坑再挖一遍。
- `project.godot` **一个字没改**：查过 `display/window/handheld/orientation = 0`（横屏）本来就是
  默认值，`stretch/aspect = keep` 会在细长手机上留左右黑边 —— 对像素画反而是对的，先这样看真机。

## SDK 就位之后跑什么

```bash
godot --headless --path game --export-debug "Android" ../dist/android/CellWar.apk
```

用 `--export-debug` 而不是 `--export-release`：debug 用那把现成的 debug.keystore 签名，
不需要另建发布密钥。装到手机：`adb install -r dist/android/CellWar.apk`。

## 2026-09-14 第一个包的实测结果

Kevin 用 Android Studio 装好 SDK 之后，**一条命令就出包了**，没有别的意外。

装出来的版本和上面写的「理论要求」不完全一样，但**不走 Gradle 就无所谓**：

| | 文档里写的 | 实际装的 | 影响 |
|---|---|---|---|
| build-tools | 35.0.0 | **36.0.0** | 没影响。Godot 打印了一句 `Could not find version of build tools that matches Target SDK, using 36.0.0` 然后照常签名 —— 预编译模板这条路只借 `apksigner`，版本不挑 |
| platform | android-35 | **android-37.0** | 没影响（只有 Gradle 那条路才编译 platform） |
| JDK | 17（Gradle 要） | 25 | 没影响。`apksigner` 在 JDK 25 上跑得动，只是会打几句 `WARNING: A restricted method in java.lang.System has been called` —— 那是 JDK 25 的原生访问警告，不是错误 |

⚠ **走 Gradle 的时候这三条就全都要补齐**（build-tools 35.0.0 / platforms;android-35 / JDK 17）。

出包命令（实际跑通的那条）：

```bash
godot --headless --path game --export-debug "Android" <绝对路径>/dist/android/CellWar.apk
```

产物 **29 MB**，另有一个 `.idsig`（apksigner 的 v4 签名附件，装机不需要它）。

验过的五条：

- **签名**：`Signer #1 CN=Godot, OU=Godot Engine` —— 就是那把 debug keystore，能装
- **包名 / 版本**：`com.springsense.cellwar`，versionName `0.1.0`，`minSdk 24` / `targetSdk 35`
- **INTERNET 权限在**（`aapt dump permissions` 确认；`dump badging` 的输出里看不到它，别被骗）
- **脚本是纯文本**：包里 **92 个裸 `.gd`、0 个 `.gdc`**，6 个 `.remap` 全是 `.tscn` → 二进制场景的正常重映射，**没有一个是 `.gd.remap`**。也就是说 `script_export_mode=0` 生效了，安卓这条线不会重蹈「补丁全是哑弹」那个坑
- **架构只有 `arm64-v8a`**（Godot 4 预设默认不带 `armeabi-v7a`）。现在的手机都是 arm64，够用；真碰到老机器再在预设里勾上

## 装到手机

```bash
%LOCALAPPDATA%/Android/Sdk/platform-tools/adb.exe install -r dist/android/CellWar.apk
```

手机要先开「开发者选项 → USB 调试」，插上后 `adb devices` 能看到设备才行。
不想插线的话，把 `dist/android/CellWar.apk` 传到手机上直接点安装也一样（需要允许「安装未知来源应用」）。

## 第二阶段：Gradle 自定义构建（2026-09-14 起，**卡在 JDK**）

### 模板不进仓库，只提交我们那份改动

装出来的 `game/android/` 是 **58 个文件、202 MB** —— `libs/` 里的预编译原生库占了全部。
这种东西进 git 一次就再也拿不出来，所以：

* `/game/android/` 进 `.gitignore`
* 仓库里只留 `tools/android/network_security_config.xml`（我们自己的改动）
  和 `tools/setup_android_build.py`（装模板 + 盖改动，可重复跑）
* 换机器 / 升 Godot 之后跑一次脚本就还原

⚠ 代价是「有人忘了跑」，而**忘了跑的后果是静默的**：包照出，只是安卓端收不到补丁。
所以出安卓包之前先跑 `python tools/setup_android_build.py --check`。

⚠ `godot --install-android-build-template` 这个命令行开关在 4.5 上**没落地**
（加不加 `--editor` 都不生成任何东西），所以脚本是自己解 `android_source.zip` 的 ——
连 Godot 认「装好了」要的那两样（`android/.build_version` 里的版本戳、
`android/build/.gdignore`）一起写。

### 明文例外是「点名放行」，不是全局裸奔

`tools/android/network_security_config.xml` 里 `base-config` 仍然
`cleartextTrafficPermitted="false"`，只给 `124.221.78.13` 开了一个 `domain-config`。
脚本把它复制到 `android/build/res/xml/`，并往清单的 `<application>` 上加一句
`android:networkSecurityConfig="@xml/network_security_config"`。

服务器换地址时**这里和 `boot.gd` 的 `SELF_HOST` 要一起改**。

### 实测：JDK 25 跑不了，必须装 JDK 17

`gradlew --version` 在 JDK 25 上是能起来的（那只是启动器），但真构建当场死：

```
BUG! exception in phase 'semantic analysis' in source unit '_BuildScript_'
Unsupported class file major version 69
```

**major version 69 就是 JDK 25**。Gradle 8.11.1 的 Groovy 解析不了它 ——
和模板 `config.gradle` 里写的 `javaVersion VERSION_17` 对得上，不是巧合。

装好 JDK 17 之后，**不用动 `JAVA_HOME`**：把 Godot 编辑器设置里的
`export/android/java_sdk_path` 指过去即可（Godot 会用它去调 Gradle）。
现在那一项指着 `C:\Program Files\Microsoft\jdk-25.0.4.7-hotspot`。

### ⚠ 导出失败时 Godot 的退出码仍然是 0

这一轮亲眼看到的：Gradle 构建失败、日志里明明白白 `ERROR: Project export for preset
"Android" failed.`，而进程**退出码是 0**。

也就是说**任何出包脚本都不能靠退出码判断成败**，必须去抓输出里的 `ERROR:` /
`Project export for preset ... failed`。真给安卓写发版脚本时这条要先接上，
否则会出现「脚本一路绿灯、产物却是上一次的旧包」——
`dist/android/` 里那个 `CellWar.apk` 正是上一次非 Gradle 那版留下的，
这次失败根本没覆盖它，而脚本层面看不出区别。

### 还要装什么（都要 Kevin 自己来）

1. **JDK 17** —— Microsoft OpenJDK 17 或 Eclipse Temurin 17 都行，和现有的 25 并存。
2. Android Studio 的 SDK Manager 里补两个（现在装的是 build-tools 36.0.0 / android-37.0，
   Gradle 这条路按 `config.gradle` 要的是 35）：
   * SDK Platforms → **Android 15.0 (API 35)**
   * SDK Tools → 勾 Show Package Details → Android SDK Build-Tools → **35.0.0**

（第 2 条还没被验证过 —— 这次构建死在 JDK 上，压根没走到查 SDK 那一步。
装好 JDK 17 再跑一次才知道还缺不缺。）

## 探路包要看的四件事

1. **能不能装、能不能起**（起不来多半是签名或 minSdk）
2. **排版**：960×540 在真机上左右黑边多宽，手牌抽屉和右栏会不会被裁
3. **像素字/贴图糊不糊**：高 DPI 屏上非整数倍缩放必糊（仓库有「贴图一律不缩放」的约定）
4. **性能**：安卓走 Mobile 渲染器（`rendering_method.mobile = mobile`），
   而桌面是 `forward_plus` —— 两条路不一样，棋盘那堆演出层值得看一眼帧数

## 还没解决的（按大小排）

- **触摸没有「悬停」**：棋盘格详情、手牌卡面详情、右栏预计收入全靠 `tile_hovered` / `card_info`
  的悬停。手指要么按下要么没有，这套在触摸上读不出来 —— 得改成「点一下出详情、再点一下执行」
  或长按。这是纯 UI 重做，量最大，单独开。
- **热更的基线号要理一条线**：`PatchState.BASE_BUILD` 是写死在脚本里的常量，
  而 `latest.json` 只有一份、地址固定。安卓包如果不是和 Windows 包同一次全量发版出来的，
  两边基线号不同 —— 得想清楚是「两个平台共用一条补丁线（同一次发版一起出包）」还是「各发各的」。
- **反馈口仍是明文**：`feedback.gd` POST 的是玩家昵称 + 正文 + 截图，那是用户内容。
  2026-09-14 选了先不动，见开发日志那条。
