## 三、目标架构

### 3.1 进程与程序集

```
core/CellWar.Core/      规则内核（已有）。纪律：零 PackageReference、纯 BCL
core/CellWar.Ai/        新：普通 / 意图 / 搜索三档 + 推演游标 + 选项适配层（P3）
core/CellWar.Sidecar/   新：控制台宿主，一个进程多会话（P1）
core/CellWar.Core.Tests/  已有，P1 起加 Sidecar / Ai 的测试
game/scripts/kernel/cw_kernel_sidecar.gd   CWKernel 的 sidecar 实现（P1）
```

- **传输**：本机回环 TCP + 一次性 token。Godot 先 `TCPServer.listen(0, "127.0.0.1")` 拿一个临时端口，再 `OS.create_process` 起 sidecar 并把 `--connect 127.0.0.1:<端口> --token <随机串>` 传过去，sidecar 连回来。这样不用解析子进程 stdout、没有端口竞争、Windows / mac / Linux 同一条路，Godot 侧全程非阻塞（`StreamPeerTCP.poll()` 每帧读一次）。
- **帧格式**：一行一个 UTF-8 JSON。请求 `{"id":n,"op":"…","sid":会话,…}`，回应 `{"re":n,…}`；sidecar 不主动推送 —— 条目由句柄每帧 `pull`。
- **多会话**：协议从第一版就带 `sid`（桌面固定 1）；服务器一个 sidecar 进程跑所有房间（服务器 3.7 GB 内存与别的服务共用，一局一进程不划算）。进程崩了：句柄进 `FAULTED`，服务器按每步的 checkpoint 重起再 `restore`（P6 做）。
- **AI 在 sidecar 里**：AI 席由 sidecar 在后台线程作答，不过网；GD 只对真人席发 `answer`。教程 NPC / 闸桥那类**脚本 decider** 留在 GD 侧，由句柄在收到对应席位的 `ask` 时本地作答（P5）。

### 3.2 条目流（与 GD InProc 逐字段同形）

句柄对消费者的形状不变：15 种条目（`cw_kernel.gd` 头注）+ `seq` 单调 + `barrier`。C# 侧新增 `HostStream`：把 `PullPresentation` 的演出条目、合成的 `ask` / `sync` / `game_over` / `log` 条目按 GD 的节拍排好（`step_end` → `sync` → `ask`；终局前 `step_end` → `sync` → `game_over`）。坐标在报文里是 `"q,r"` 串，句柄转回 `Vector2i`。**roll 的 barrier**：C# 引擎不等动画（设计如此），句柄侧 `ack` 为空操作 —— 演出顺序由 `CWPlayQueue` 保证，这在联机路上已经跑了两周。

### 3.3 不变量（每条都要有护栏）

1. `boot.gd` / `patch_state.gd` 永不依赖 sidecar；sidecar 起不来 = 句柄 `UNAVAILABLE`，单机 / 热座 / 教程置灰、联机照常，**绝不计进 STRIKES**。
2. `CellWar.Core` / `CellWar.Ai` 零 PackageReference；sidecar 永不 `PublishTrimmed` / `PublishSingleFile` / `PublishAot`（发版闸守）。
3. 同一局同一套规则：不做对局中途换 dll。
4. 握手只闸宿主 ABI（`host_abi`），规则 build 与 `ruleset_digest` 只上报不闸。
5. 产品代码里持 `CWGame` 的地方只减不增（结构闸 `t_no_engine_in_ui` 继续守 UI）。

## 四、阶段、交付与验收

### P1 · sidecar 宿主 + `CWKernelSidecar`（地基）
- **C#**：`CellWar.Sidecar`（会话表、回环连接 + token、`hello` / `version` / `selftest`、`open` / `close` / `pull` / `answer` / `observe` / `save` / `restore` / `abort`）；`HostStream` 合成 15 种条目；退出码 64 / 65 / 66（连不上 / token 错 / 自检失败）。
- **GD**：`cw_kernel_sidecar.gd` 真实现（起进程、握手、超时、条目转换、`UNAVAILABLE` / `FAULTED`）；一个开发开关（设置项或命令行）让单机局走 sidecar，默认仍走 InProc。
- **验收**：无头测试里起真 sidecar，两席都用语义键 LCG 决策者打完整局（与 L1 KeyWalk 同一套），条目流形状过 CWMirror 装载；sidecar 杀掉 → `FAULTED` 且 UI 不崩；起不来 → `UNAVAILABLE` 且不碰补丁状态。真机热座打一局截图。

### P2 · 日志原文 + 观测补齐
- 结构化日志事件 `LogLine(Key, Args, SecretSeat, PublicKey)` 走 Stage 作用域；C# 模板表（初稿从 GD 179 处格式串收割）；秘密行、`log_run` 合并、名字注入、Outbox 改绝对下标。
- tier B 派生字段、`ask` 选项 data 与 GD 同形、名字 / `mark_player` / `surrender` / `log_msg`、`cancer_types` / `rules` / `names` 开局参数、查询补 `cost_effects_for` / `move_block_reason`。
- **验收**：L1 四条轨迹逐步比**日志行**与演出条目（envelope 对拍加 logs 段）；`headless_test` 里那批中文子串断言改成对照闸。

### P3 · AI 三档进 C#
- `CellWar.Ai`：推演游标（照 `RuleFlow.Continue` 推到回合边界）、选项适配层（语义键 → GD 形状字段）、普通档（约 520 行 GD）、意图档（约 190）、搜索档（alpha-beta，约 60 + 共用）；`MatchSession` 加给同进程 AI 的全知只读口。
- **验收（不扫胜率）**：录一份共享局面语料（GD 无头自对弈，每个决策点导出世界 + rng + 选项 + 三档答案），C# 装回来比答案键 —— 普通档 100% 一致；意图 / 搜索档候选读数逐字段相等、最终键一致；每条不一致都要归因。先把 GD 参照里的不确定性去掉（距离场缓存、非稳定排序）。冒烟：三档自对弈只断言合法、能终局、单问耗时 p95。变异检验。语料冻结进仓。

## 五、Kevin 10-01 追加四答（同日，全部按推荐）


1. **意图 / 搜索档的试走骰子 → 改成独立随机流**：GD 现在试走用的是真局接下来要掷的骰子（等于偷看未来，09-01 扁平 MC 修过同一种问题）。C# 版试走用一条从局面派生的独立随机流；对拍时 GD 参照一侧也换同一条流（同一个算法两边各实现一份），照样逐决策比对。强度会和线上现在的意图 / 搜索档略有不同。

3. **AI 档位 → 全部统一成三档「普通 / 意图 / 搜索」**：单机、联机房间、网页单机同名同义。
4. **代码签名证书 → 先真机测再定**：P7 在 3～5 台装了常见杀软的真机上测，拦得厉害再买。

## 六、风险

1. **规则还在动**：切换前每次规则改动两侧同改，漏一侧 L0 / L1 会红 —— 这是好事，别关闸。
2. **性能未知**：搜索档每问约 25 次整回合模拟，C# 侧零基准；P3 要先量。
3. **杀软 / Gatekeeper**：只能真机撞，P7 要 3～5 台机器。
4. **服务器内存**：一个进程多会话 + `DOTNET_GCHeapHardLimit`，P6 实测。
5. **切换不可逆的是客户端**：Release 装上就回不去（`boot.gd` 没有降级档），所以 P8 的顺序是「客户端先、服务器后、旧服务器目录留 N 天」。
