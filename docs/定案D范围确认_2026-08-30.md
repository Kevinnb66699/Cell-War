# 定案 D 的实装范围确认（2026-08-30）

**一句话**：Kevin 拍板的是**一个场景**（组织巡航 + 组织驻留 互相浪费免费额度），
我实装的是**一条通用判据**，结果多管了 5 处没点名的地方。**需要确认是维持还是收窄。**

已实装并全绿（703 项检查），但这一条的范围是我自己扩的，先摆在这里等拍板。

---

## 一、你说的 vs 我做的

| | 内容 |
|---|---|
| **Kevin 原话** | 「不是有意为之，要省免费额度」——针对审查问题 6：同时装【组织巡航】+【组织驻留】时，本回合第一次向健康组织移动会把**两个**「首次免费」额度一起烧掉 |
| **我实装的判据** | 「这一次算出来的价钱和进来时一样 → 这张卡没起作用 → 它的次数/闸门/额度都留着」——对移动费链上的**每一张**卡一视同仁 |

差别的来源：旧代码的消耗逻辑（`_spend_move_mods`）**只看目的地是什么组织**，
从不看这张卡这一次有没有真的改到钱。所以「白烧」不止 Kevin 看到的那一处，
一共有 6 处；通用判据一次全兜住了。

## 二、七个消耗点，谁被点名了

| 卡 / 技能 | 消耗的是什么 | 什么情况下会「白烧」 | 是否点名 |
|---|---|---|---|
| 组织驻留 | 每行动回合首次向健康组织免费 | 组织巡航已经让这次免费 | ✅ **点名** |
| 组织巡航 | 每行动回合首移免费 | 组织驻留先让这次免费（顺序反过来） | ✅ **点名** |
| CXCR3趋化 | 限次 2 次 | 价钱已踩到 0.2 下限，减不动 | ❌ 顺手带上 |
| LFA-1黏附 | 每行动回合首次闸门 | 同上 | ❌ 顺手带上 |
| 炎症趋化 | 打出后的一次性条目 | 价钱正好已经是 0.5，改不动 | ❌ 顺手带上 |
| 上皮—间质转化 | 限次 1/2/3 次（按分期） | 基准已是 0.2（伪足穿透），改不动 | ❌ 顺手带上 |
| 迁移激活（世界事件） | 每细胞每回合一次免费移动 | 价钱已经是 0 | ❌ 顺手带上 |
| 癌症干性 | 复活当回合的限次额度 | —— 0.2 → 0 确实改了钱，**行为不变** | — |
| 组织浸润 | （无额度） | —— 本来就没东西可省，**行为不变** | — |

## 三、实测数据

全部在引擎里实跑取证，探针脚本跑完即删。

### 点名的那处

```
巡航闸门烧 / 驻留闸门烧        true / false    ← 驻留的额度留住了
```

### 顺手带上①：CXCR3趋化 价钱已到下限

X 级基准 0.5，【组织浸润】先减 0.3 已踩到 `MOVE_CUT_MIN`，CXCR3 再减也减不动：

```
报价                    0.2
CXCR3 剩余次数           2        ← 旧版会变 1
```

### 顺手带上②：LFA-1黏附 价钱已到下限

```
报价                    0.2
LFA-1 闸门是否已烧        false    ← 旧版 true
```

### 顺手带上③：炎症趋化 遇上价钱正好已经是 0.5

I 级基准 1.0 → 先打【CXCR3趋化】压到 0.5 → 再打【炎症趋化】「改为 0.5」，改不动：

```
基准价                                  1.0
报价（CXCR3 压到 0.5，炎症趋化改不动）        0.5
CXCR3 剩余次数（它确实减了钱，照常消耗）        1
炎症趋化 条目还在                          true     ← 旧版会被吃掉
```

⚠ 这条和**定案 A 是同一张卡的两面**：价钱低于 0.5 时它**抬价**（A 说保留抬价），
价钱正好等于 0.5 时它**什么也没干**（D 说别消耗）。两条定案在这张卡上会同时生效。

### 顺手带上④：上皮—间质转化 遇上伪足穿透

黑色素瘤【伪足穿透】把基准价压到 0.2，EMT 的「改为 0.2」改不动：

```
dest 邻接癌性组织数        2
基准价                   0.2      ← 伪足穿透生效
报价（改为 0.2 = 没变）     0.2
EMT 剩余次数              3        ← 旧版会变 2
```

### 顺手带上⑤：迁移激活 在价钱已经是 0 时

```
迁移激活额度还在           true     ← 旧版会被吃掉
```

**这条是里面最粗的一个**：旧代码的 `consume_free_move` 在 `_do_move` 开头
**无条件调用**，只要事件在场，免疫细胞每次移动都消耗掉那份额度，
哪怕这一次是靠【组织巡航】免费的、跟迁移激活半点关系没有。

## 四、我为什么扩大了范围

**① 只修点名的两张会留下同类不一致。** 同样是「有限资源被白烧、玩家从报价上
完全看不出来」，很难解释凭什么组织驻留该省、CXCR3 不该省。这条不一致下次审查
我还得再报一遍。

**② 开特例要维护一张豁免名单，而那正是问题 6 的成因。** 旧版「报价」和「收费」
是分开写的两份谓词，靠一句注释要求「必须一字不差」，问题 6 就长在那条缝里。
若按卡开特例，等于在合并后的函数里重新引入一张要人工保持同步的表。

**③ 通用判据只有一行。** 实现就是 `if after == cost: return cost`——
「没改变数值就等于没结算」，不需要任何卡名列表。

## 五、代价（必须讲清楚）

**这是一次全面倒向玩家的削弱**：移动费相关的所有限次资源都变得更耐用了。
单次数值不大（每次省 0.2~0.5），但会让【CXCR3趋化】【上皮—间质转化】这类卡的
**实际可用次数变多**，【迁移激活】的价值也上升。

⚠ **平衡影响没有测过。** 如果要评估，应该跑一轮 AI 互搏对比。

---

## 六、要收窄的话，怎么收

把判据从「所有卡」缩成只管**「变 0」类**（组织巡航首移、组织驻留、迁移激活），
恢复 ①③④ 的旧行为——也就是说：**免费额度省，限次折扣不省。**

改动在 `cw_actions._apply_move_card` 里给 `spend` 加个条件，五行以内；
对应的三条断言也好改。
