# 平衡扫描 2026-09-05 · 呼吸改版与无氧系数 c 定值

> **§1 方法在跑出任何结果之前写定**，和 [智能体对弈记录_2026-09-05](智能体对弈记录_2026-09-05.md) 同一个规矩：
> 先说清「怎么算才算数」，免得看到数字之后再去挑口径。

## 1. 要回答的问题与判据（先写）

**要定的只有一个数**：【E-无氧呼吸】新公式 `c × √(块内癌格子数) ÷ 块内癌细胞数` 里的 `c`。
团队 2026-09-04 定案时把 c 交给测试定值，其余四条规则（有氧等级式、记忆门槛 10/20、
分化降 II 级、抗体递减保留）是**给定条件，不参与扫描**。

**判据**：四人局与六人局的癌方胜率都尽量靠近 50%，回合数落在团队 09-04 说的
「15 回合以内都可以接受」。两个人数档冲突时以**六人局**为准 —— 六人局是实际开团的场次。

**基准 AI 用蒙特卡洛（`ai=mc`），不是启发式。** 团队指定「用 MC 来测试」。
这条很重要：本项目历史上启发式与 MC 两把标尺在同一配置下差过 50~70 个百分点，
两者的数字**不可互相换算、不可混用**。本页所有数字都是 MC。

**局数与置信区间**：粗扫每档 24 局，定值档补到 60 局以上。
24 局的 95% Wilson 区间宽约 ±20 个百分点 —— **粗扫只用来定区间，不用来定数**。
凡是拿粗扫数字当结论的地方，本页都会写明。

**种子**：`balance_scan.gd` 固定 `20260800 + 局号`，同参数重跑逐位一致。
不同档之间共用同一批种子，所以档与档的差是**规则差**，不是运气差。

**已知的方法学限制**（09-05 智能体对局记下的三条，这里照样成立）：
MC 是一把**标尺**不是真人；它测得出「哪一档更偏哪边」，测不出真人会不会发现某个套路。
所以本页的产出是**一个 c 的取值区间加一个推荐值**，不是「平衡已完成」。

## 2. 扫描过程

### 2.1 第一批：四人局粗扫 c（每档 24 局 MC，`order=ICIC`）

先跑了一档 c = 2.0（引擎当时的默认值，20 局）拿手感，结果癌胜只有 10%，于是往上扫。

| c（十分能量） | 癌胜 | 平均回合 | 终局癌性格数 |
|---|---|---|---|
| 2.0 | 10% (2/20) | 12.3 | 24.9 |
| 2.6 | 29% (7/24) | 10.2 | 47.9 |
| 3.2 | 25% (6/24) | 10.8 | 45.8 |
| 3.8 | 25% (6/24) | 11.4 | — |
| 4.4 | 37% (9/24) | 11.5 | — |

24 局的 95% Wilson 区间宽约 ±19 个百分点，所以 **2.6 / 3.2 / 3.8 三档彼此分不开**；
能说的只有「2.0 明显偏低、4.4 明显高于 2.0」。**这张表定不了 c，只定了搜索方向。**

### 2.2 中途发现：癌方不是输在没钱，是被清场

c = 3.2 那档的胜法分解是决定性的：

```
胜法：cancer_weighted 6, immune_clear 17, limit_immune 1
每局占地：癌【定殖】127.6 + 【增生】22.3 vs 免疫【净化】98.7（转化比 1.5:1）
每局攻击：发动 5.8 次（失败 1.7）· 双方死亡 6.7（免疫 3.9 / 癌 2.8）
```

**24 局里 17 局是癌细胞被打光**（`immune_clear`），只有 6 局是占地赢。
而占地本身癌方是领先的 —— 每局净转化 150 格 vs 免疫净化 98.7 格，比例 1.5:1；
终局癌性格数 45.8 格，离占地胜利要的 90 加权格差一半，**局就已经结束了**。

c 提高的是**每回合进账**。癌细胞死不死跟钱关系不大：它们缺的是复活据点（固化）
和挨打时的生存手段。这解释了为什么 2.6→3.8 加了 46% 的收入，胜率一动不动。

三档的胜法分解几乎一模一样（`immune_clear` 恒为 17），进一步坐实了这一点。

### 2.3 旧规则对照档：MC 下的旧基线比记忆里低得多

`abase=0 asqrt=0 abhalf=0 difflv=2 emax=150 ecap=9990`（把 09-04 定案全关掉，
只有记忆门槛因为是常量关不掉）：

| 旧规则 · MC · 24 局 | 癌胜 | 平均回合 | 净化次数 |
|---|---|---|---|
| 四人局 | 37% (9/24) | 8.0 | 51.5 |
| 六人局 | 29% (7/24) | 8.0 | — |

**这一档纠正了一个错误前提。** 此前笔记里记的基线是「六人 45% / 四人 46%」，
我一度拿它当参照，判断本次改动「把癌方削掉了 15~20 个点」。
那个 45/46% 是**启发式**量的，不是 MC —— 本项目历史上两把标尺在同一配置下
差过 50~70 个百分点。MC 下的旧基线本来就是 37% / 29%，癌方原本就在挨打。

顺带一个白赚的结论：新规则把对局从 8.0 回合拉到 10~11.5 回合，
净化次数 51.5 → 98.7（近乎翻倍）。旧规则下 8 回合就结束，双方几乎没有来回。

### 2.4 中途改配置 → 第一批全部作废，重扫

团队 09-05 复核时又定了两条：**取消所有能量上限**、**分化撤回 III 级**。
这两条都改变了引擎默认值，于是 2.1~2.3 的 c 扫描**全部作废**（它们量的是另一套规则）。
重扫之后第一个数就说明了差距有多大：

| c = 4.4 · 四人局 · MC · 24 局 | 癌胜 | 平均回合 |
|---|---|---|
| 旧配置（有上限、分化在 II） | 37% | 11.5 |
| **最终配置（无上限、分化 III）** | **70%** | 11.8 |

**取消能量上限是本轮影响最大的一条。** 胜法分解从「占地 6 / 被清场 17」翻成
「占地 15 / 被清场 5」，每局占地从 150 格涨到 224 格。
原因在 09-05 智能体对局里已经看到过：15.0 那道天花板**只在削癌方**
（三个癌细胞第 4~5 回合就顶到上限溢出浪费），免疫方从没碰到过；一取消，
癌方那部分本来被浪费掉的收入立刻兑现成占地。

所以 c 的落点比按旧配置估的**低得多** —— c = 5.0 / 5.6 两档当场停掉（只会更高），
改扫 c = 2.6 / 3.2，四人六人同时。

### 2.5 一个要单独盯的组合

c = 4.4 最终配置下，**恶性黑色素瘤 + 小细胞肺癌同场是 4/4 = 100%，平均 5.5 回合**。
这个组合在 09-03 的记录里就是 88%，取消上限之后更极端。
**它大概率压不住在 c 这一个旋钮上** —— c 调到让整体 50% 时，
这个组合仍会显著高于其余组合。留给团队单独决策，本页只负责把数字摆出来。

### 2.6 第二批定案落地后：全场 94~100% 癌胜 —— 是 bug，不是平衡

团队 09-05 第二批（有氧按人数均分、坏死/黏液补效果、无氧改回合末、骨肉瘤重做）落地后
重扫启发式 c 网格：**四人 94~100%、六人 98~100%，c 从 2.0 到 5.0 全无区别**。

新加的回归 `t_batch2_rules` 第一条同时红了：3 个免疫各应拿 2.5 ÷ 3 = 0.8，实得 **2.0**。
`_aerobic()` 的顺序是 算基准 → 均分 → 套 2.0 低保，低保把 0.8 顶回去，**均分等于没开**，
每人 2.0 —— 正是 2.2 节里 `abase=20` 那一行的 88~89%，再叠上其余四条对癌方有利的改动。
`aerobic_split` 此前一直是关着的实验档，所以这个顺序问题从没暴露。修法：夹钳挪到均分之前。

**方法学教训（第四条）**：规则叠着改的时候，每加一条都得看一眼「它和已有的夹钳/低保/封顶怎么交互」。
低保是为旧盘面公式设的（那时它管的是每人份额），换成等级式 + 均分之后它的语义变了，没人重读它。

### 2.7 修完低保之后：阵营总额多少？

均分之下「2.5 不动」有两种读法，差一倍：每人基数 2.5 ÷ 人数（总额 2.5，按**一个**细胞标定），
或四人局每人仍 2.5（总额 5.0）。修完低保后扫总额 × c（启发式 200 局，纯 ÷ 人数）：

| 阵营总额（4p 每人 / 6p 每人） | 4p c=2.6 | 4p c=3.8 | 6p c=2.6 | 6p c=3.8 |
|---|---|---|---|---|
| 2.5（1.25 / 0.83） | 98% | 99% | 100% | 100% |
| 4.0（2.0 / 1.3） | 97% | 97% | 100% | 99% |
| 5.0（2.5 / 1.7） | 79% | 93% | 99% | 99% |
| 6.0（3.0 / 2.0） | 57% | 76% | 96% | 98% |

**总额 2.5 那种读法数据上直接排除**。六人局在启发式下每人 2.0 仍是 96%+ ——
但 2.3 节已经证明启发式六人局比 MC 偏癌方 30 多个点（同配置 52% vs 16~20%），
**这张表定不了六人局**，只定了四人局的形状（每人 2.5~3.0 之间）。

### 2.8 落地的口径与 MC 确认设计

落地：`aerobic_split_ref = 2` —— **按 2 个免疫细胞的量（5.0）标定，≤2 个每人全额，>2 个把 5.0 均分**。
二人局、四人局每人仍 2.5（团队原话「2.5 不动」），只把六人局从 2.5 拉到 1.7。
没选「总额直接设 5.0 再纯均分」是因为那会让二人局免疫变成每人 5.0，团队没有要过这个。
**此口径待团队拍板**；`asplitref=0` 是纯 ÷ 人数的对照档。

MC 确认（24 局/档）同时跑五档：四人/六人 × c = 2.6 / 3.2 在总额 5.0 下，
外加六人局 c=2.6 在每人 1.3 与 2.0 两档 —— 后者是为了拿到**六人局对免疫收入的斜率**，
只有一个点定不了数。结果见 §3。

### 2.10 两档在低 c 处收敛 —— 这是真正的线索

把所有 24 局 MC 点按「同一 c 下，四人局 / 六人局各自要多少免疫每人收入才到 50%」内插：

| c | 四人局 50% 线 | 六人局 50% 线 | 差 |
|---|---|---|---|
| 2.6 | 每人 ≈2.45（2.0→87%、2.5→41%） | 每人 ≈2.05（1.7→83%、2.0→54~58%） | 0.4 |
| 2.0 | 每人 ≈1.8（2.0→41%、2.5→20%） | 每人 ≈1.75（1.7→58%、2.0→25%） | **≈0** |

**c 越低，两档要的免疫收入越接近**。所以「一个共用 c + 一个共用基数」并非注定顾不了两头 ——
在 c=2.0 附近、每人 ≈1.8、不均分，两档都落在 50% 线上。这是第五个候选 **(e)**，正在跑。

⚠ (e) 有一个陷阱：`aerobic_floor` 的低保是 2.0，基数 1.8 会被它**静默顶回 2.0**（和 2.6 节均分被顶回去是同一类问题）。
等级式有自己的基数，这条低保已无存在理由；(e) 用 `afloor=0` 跑，落地时也该把默认低保关掉或降到基数以下。

代价方向：免疫收入越低对局越短。(d) 四人 c=2.0 是 13.8 回合，(e) 每人再少 0.2，估计 14~15 回合，贴着「15 以内」的线。

顺带修一处回显：`_applied()` 里一条老逻辑在 `aerobic_split` 与默认不同时打 `tune=split`，
默认翻成 true 之后它在**关掉**均分时也打这四个字，与同行的 `asplit=0` 打架。删掉那条老逻辑。

### 2.11 (e) 实测：我的收敛预测错了

(e) 不均分、每人 1.8、低保关、c=2.0：**四人 66% (16/24) · 11.2 回合，六人 41% (10/24) · 11.6 回合**。
预测是两档 ≈50%，实得 66 / 41 —— 和 (d) c=2.3 的 70 / 41 几乎一样。
2.10 节那张「50% 线」内插表是在 ±19 个百分点的 24 局档上做的，把噪声当成了斜率。**记一笔，别再用 24 局档做内插。**

不过把所有不均分的点摆到一起，一条更硬的规律出来了：

| 不均分 · 每人 / c | 四人局 | 六人局 | 差 |
|---|---|---|---|
| 2.0 / 2.0 | 41% | 25% | 16 |
| 1.8 / 2.0 | 66% | 41% | 25 |
| 2.0 / 2.3 | 70% | 41% | 29 |
| 2.0 / 2.6 | 87% | 58% | 29 |

**在任何共用的（基数, c）下，四人局都比六人局偏癌方 16~29 个点**。原因不难懂：四人局 2 个免疫对 2 个癌，
每一个免疫细胞的收入变化对局面的影响都比六人局的 1/3 大 —— 四人局对免疫收入更敏感（1.8→2.0 四人动了 25 点、六人 16 点）。
所以「一个共用基数 + 一个共用 c」结构上顾不了两头，差不是噪声。

### 2.12 顺着引擎已有的思路：基数按人数分档 —— 候选 (f)

引擎对「人数不对称」已经有一个现成的处理：**初始癌组织按人数分档**（四人 15 / 六人 24，`CWTuning.init_cancer_tiles`），
注释原话是「人越多免疫越强，用开局布局补回来」。同一个思路挪到有氧基数上：

**(f) 不均分、c=2.0~2.1、四人局每人 2.0、六人局每人 1.8**。两个点其实都已经量过：
四人 2.0 / c=2.0 → 41%，六人 1.8 / c=2.0 → 41%。两档同一个数、同一侧（略偏免疫），把 c 从 2.0 挪到 2.1 应能把两档一起抬向 50%。
确认档（四人 `abase=20` / 六人 `abase=18 afloor=0`，`asqrt=21`）在跑。

落地方式：`AEROBIC_LEVEL_BASE` 从一个数变成按人数取的表（同 `INIT_CANCER_TILES` 的写法），旋钮 `abase` 仍可整体覆盖。

**推荐落地：方案 (f) + c = 2.0。** 具体：

  收入低保 2.0 关掉（否则把六人局的 1.8 静默顶回 2.0）。
- 【E-无氧呼吸】c = 2.0。
