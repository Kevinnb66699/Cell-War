### 0.2 总设计口径：**最小 diff 的机械切换**

三条原则，按优先级：

1. **能不改就不改。** 结构（`_process` 每帧全量刷新、`CWUIBridge` 的继承链、`cw_room` 的席位表/等待室/重连/投票、`_ask_action` 的两段式主循环、`CWLogPanel` 的 `_built` 游标增量折行）**一律原样保留**。
2. **改名优先于改结构。** 凡是「加一个字段 / 改一个类型标注」能解决的，不许改控制流。
3. **切通优先于优化。** 性能、协议增量、AI 拆桥、教程 C# 化一律不在本批。

三处**故意**违反最小 diff，各有不可替代的理由：
* `match.gd` 的字段 `game` 改名为 `mirror`（A-1.1：让 `grep` 成为可执行的结构闸）；
* `CWPlayQueue` 上线（A-1.4：`_net_loop` 与四个 Godot 信号必须并成一条，否则两条演出通路口径永远漂）；
* 读侧比写侧早一步翻面（C-1 步 6 的脚手架，来自 risk §0.3：把一次巨型手术拆成可 revert 的两步，并把「每帧全量 observe 贵不贵」这个未知数提前量到）。

### 0.5 为什么骨架取 minimal

三名评委各推一份、总分打平。裁决依据是**本批风险最高的那一个面**：服务器侧。

* minimal 的 `adopt`（不安装 `CWKernelBridge`）+ `autorun: false` 是**唯一**同时做到三件事的设计：① 兑现拍板 1(a)（`cw_room.gd:start` 那十行、`_name_seats()` 的位置、`_teardown_game` 的六行、`cw_net_bridge.gd:ask` 那两行救命的 `push_state` + `next_frame` **全部一字不动**）；② 不让联机演出变黑（§0.4 #8）；③ 不需要在服务器上新起一套队列 + flush 机制（risk 的 R14 与 test 的缺口都由此消失）。
* minimal 的源码保真度最高：`cw_room.answer` 必须现算 key、`_ask_action` 的 `cell` 取一次、`has_consumer` 只在 `_on_roll` 一处 —— 这三条只有它答对，而三条都直接决定实现写法。

risk 与 test 的高价值部分整体嫁接：risk 贡献**分步结构**（读侧先翻面 + go/no-go 预算闸）、`cw_mirror._normalize` 还原 `Vector2i`、`asking_pid` 天然正确、`CWFeedback.pack` 读顶层键、`cell_half_height` 该读节点层；test 贡献**护栏体系**（`t_kernel_parity` / `t_no_engine_in_ui` 先证明有判别力 / `t_ai_same_hash`）、精确计量、`show_notice`、`CWMatch.REPLAY_ON` 与服务器回放柜撞号。

#### A-1.5 观测节拍：**每次问人之前一份、终局之前一份**

写死在 `cw_kernel_inproc.gd:_on_ask` 与 `:_run`（B-2 ⑥）：`observe_viewer` 被设置时，`_on_ask` 在转交 decider（或 `_push("ask")`）**之前**先 `_push("sync", {"envelope": CWObsCodec.encode(game, {...})})`；`_run` 在 `_push("game_over")` 之前同样先推一份。⚠ 复核指出这与三处正本冲突（`docs/观测协议_v1.md` 附录 B、`cw_kernel.gd` 文件头、`cw_kernel_inproc.gd` 注释都写着「`sync` 传输层专用，InProc 永不发」）—— **这三处列进 B-1 的同批改动清单，按协议 §九 走版本纪律**（p 1→2 那一次一起改），不能留「代码这么干、正本写着永不这么干」。

**为什么是这个粒度**：① 每帧 observe 要对 127 格逐格算 `pressure_at` / `proliferate_chance`、逐细胞算 `action_kinds` / `status_rows`，再经 `CWMirror._validate` 全量走一遍未知键与零浮点检查 —— 附录 D 实测一份全量 envelope 是 43~53 KB 量级的字典构造；② 这个节拍**就是今天联机路的节拍**（`cw_net_bridge.gd:ask` 开头 `room.push_state(pid)`，文件头写明「询问前推一次 = 每步都推到了」），而传送溶解、黏液、侵蚀这几样差分演出**今天在联机局是正常工作的** ⇒ 粒度已被线上验证。

⚠ **一条玩家可见的行为变化，要拍板（E-4）并写进提交信息**：本地局的盘面刷新从「引擎边算边变」变成「一次结算完整落地」。一张多段结算的卡今天在本地逐步可见，批 1 之后与联机一样整段落地。这是从「本地比联机好」回归到「两条路一致」。退路：`_push` 里加一个演出种类白名单也推 sync，代价是每局多几百次 encode。

### A-7 · 对局日志：`CWLogStore`（新文件 `game/scripts/ui/cw_log_store.gd`）

```gdscript
class_name CWLogStore
extends RefCounted
var logs: PackedStringArray = []        ## 与 CWGame 同名 —— 面板函数体一个字不改
var log_secret: PackedInt32Array = []
var log_public: PackedStringArray = []

func apply(e: Dictionary) -> void       ## log{index, text, secret_pid, public_text}；index 越界就补齐再写
func reset_from(from: int, lines: Array) -> void   ## 重连 / 换局：整卷重灌
func clear() -> void
static func of(game: CWGame) -> CWLogStore        ## 只给测试与步 5 的过渡适配器用
```

**为什么是这个形状**：已核 `log_panel.gd:refresh` / `_rebuild_rows` / `line_text` 与 `log_hint.gd:refresh` **只**碰 `logs` / `log_secret` / `log_public` 三条并行数组，并靠 `_built` 游标增量折行、末条每帧重折、`logs.size() < _built` 判缩短即整卷重折。名字保持一致 ⇒ 这四个函数体**一行不动**，只换形参类型，`t_log_panel` 的 28 条断言一条不改。

两条喂料路（互斥）：

| 路 | 来源 | 处理 |
|---|---|---|
| 本地 / 热座 / 教程 / 回放（InProc） | `queue.on_log` 的 `log{index,…}` 条目 | `apply()`。`index` 与上一条相同 = 就地改写末条（装得下 `CWGame.log_run` 的语义）。`queue.viewer = -2` ⇒ `_crop` 不裁、三元组完整 ⇒ **热座换手时 UI 侧按 `current_human` 重筛，与今天逐字相同，不需要整卷重拉** |
| 联机（Remote） | `queue.on_sync` 的 `envelope["logs"] = {from, lines}` | `reset_from(from, lines)` 的增量形态：`for i: apply({index: from+i, text: lines[i], secret_pid: -1, public_text: lines[i]})` —— 服务器已按席位裁好（`CWNet.logs_for`），与今天把 `m["logs"]` 灌进 `shadow.logs`、`log_secret` 为空、`line_text` 自动落回原文的行为逐字等价 |

换局边界（`game_no` 变了）→ `clear()`，对应今天 `_apply_state` 里的 `shadow.logs = []`。
⇒ **`CWKernelRemote.logs_for()` 在批 1 不需要实现**。`CWKernelInProc.logs_for()` 仍要修 `open_hands`（B-2 ⑨），服务器侧观众全见档要它。
**顺带修好一个今天的 bug**：`log_run` 就地改写末条时，联机路的 `_log_cursor` 已经越过那一行 ⇒ 改写永久丢失。按 `index` 覆写后本地与联机一致。（行为变化，写进开发日志。）

## E. 要 Kevin 拍板的（只列真阻塞批 1 的四条，附我的推荐）

### E-1 · 联机的四条 query 怎么办？（阻塞报文设计；升 `NET_VERSION` 的窗口只有一次）

今天联机有路径规划（拖拽画路线 + 逐段报价 + `MARK_PLAN_BAD`）、灰格理由、技能「当前影响」，全靠 `_client.shadow` 是一个真 `CWGame`。批 1 锁到镜像之后这三样需要新出口。

* **(a) 新增 `query` / `query_result` RPC + 按 `envelope.rev` 缓存** ← **我推荐**
  实现量约 30 行（`cw_net_server._handle` 一支 + `cw_room` 一个转发 + `cw_net_client` 一个 promise 表 + `CWKernelRemote.query`）。代价是路径预览比光标晚 50~150 ms。
  **两条我核过、让这条比看起来更划算的事实**：① `ui_bridge.gd:_plan_extend` 的**第一步不问 `plan_next_dests`**（用这一问自己的高亮格），最常见的「一步规划」只需一次 `quote_path`；② 这些 query 只在**本席被问的那段时间**发生，而那时服务器正 `await room.ask_human` 的 `Waiter` 空转 ⇒ **不占服务器吞吐**。UI 侧再做成「线条立即画、价签回来再填」，手感损失可控。
* **(b) 批 1 联机局暂时退回单步迁移**（由 `caps().query_sync` 关掉规划器，不画多步路线、不出灰格理由与「当前影响」），query RPC 跟批 2 的 AI 纯查询 RPC 一起做（迁移计划 §二 明写这两批是同一批函数，「做一次算两笔」）。零延迟风险、零新报文，但联机玩家会明显觉得功能被拿走了。降级必须**可见**（不出规划提示行），不能静默画错价。
* ~~(c) 客户端用 envelope 现搭只读 `CWGame` 本地算~~ —— **已否决**，证据见 §0.6 / §0.4 #7（envelope 的 `g.tune` 只有 9 项、`RULE_FIELDS` 有 63 项，移动费那一整套旋钮一个都不在；`flow`/`pending` 是豁免键；`events.data` 压平不可逆）。

**要定的就是 (a) 还是 (b)。** 定不了就没法写 `cw_net.gd` 的报文一览、也没法定 `NET_VERSION` 30 的内容。

### E-2 · `CWUIBridge` 拆不拆 AI 继承？（阻塞步 8 的范围与结构闸的性质）

今天 `class_name CWUIBridge extends CWMonteCarloBridge` —— 桥自己就是 AI。

* **(a) 不拆，用 `attach_engine`（A-5.3）** ← **我推荐**
  五行代码：`open()` 里 `if d.has_method("attach_engine")`，`ui_bridge` 里 `func attach_engine(g)`。效果是 `match.gd` 零 `CWGame`、`ui_bridge.gd` 的 `game.` 读用法降到 0，结构闸落地，白名单只留那一行（带 `## KERNEL-ENGINE-OK`）。`t_ui_bridge` 的「非人类退回启发式」、`t_guide_bridge` 的「无界面退回 AI 代答」、`t_human_ask` ⑤、`CWUIBridge.new().enabled == false` 四条断言**一条不改**。代价：闸上有一行白名单，不是「结构上做不到别的」。
* **(b) 批 1 就拆成组合**（`extends CWBridge` + `var ai: CWBridge`）：闸变成硬的，但要动 `_wire_bridge` 的 5 个 AI 旋钮接线、`ask()` 的第三岔、上述 4 条断言，约 +1.5 人天，并且必须有 `t_ai_same_hash` 兜底才敢动平衡标尺。

**推荐 (a)**：批 1 已经够大，拍板本来就把 AI 划给批 2；一行白名单的闸和零白名单的闸，对「批 2/批 3 不会重新长出 `game.`」的防护力差别不大（`t_ai_same_hash` 无论选哪条都要做）。

### E-3 · 老档 / 老回放作废，玩家那边怎么交代？（阻塞步 9/10）
