## 一、【炎症趋化】的「降为 0.5」会把价钱抬高（高）

### 复现

```
只有【组织巡航】，首移→癌组织              0.0
先【组织巡航】后【炎症趋化】                0.5   ← 打了一张打折卡，反而贵了 0.5
先【炎症趋化】后【组织巡航】                0.0
X级 先【CXCR3】后【炎症趋化】(基准 0.5)     0.5
X级 先【炎症趋化】后【CXCR3】(基准 0.5)     0.2
```

而且**卡照样被消耗**：

```
报价                        0.5
实付能量                     0.5
移动后【炎症趋化】还剩几条      0        ← 卡被吃掉
移动后【组织巡航】首移闸门      已烧      ← 每回合额度也没了
```

玩家花掉一张手牌 + 一个每回合免费额度，换来的是多付 0.5 能量。

### 根因

`cw_actions.gd:221`（`_apply_move_card`）：

```gdscript
"炎症趋化":
    if to_cancerous:
        return CWData.INFLAM_CHEMO_COST      ## 降为 0.5
```

新通则里「降为 X」的定义是**改写**，所以代码无条件返回 0.5。上一轮我们只给「-X」类加了 `_cut_cost` 的「只降不升」钳位，「降为」类没有对应保护。

### 波及范围

**只有【炎症趋化】一张卡中招**，其余四张「降为/变 0」类都抬不了价：

- 【上皮—间质转化】降为 0.2 —— 癌方基准价最低就是 0.2（黑色素瘤【伪足穿透】），碰不到更低的数
- 【组织驻留】【组织巡航】首移、【癌症干性】—— 都是变 0，只可能降

触发条件也不刁钻：免疫细胞装了【组织巡航】（永久技能）之后再打【炎症趋化】（即时卡）就会遇到；或者 X 级基准价 0.5 时先打【CXCR3趋化】再打【炎症趋化】。

### 处理建议

两条路，**必须团队拍板**：

- **(a) 把「降为 X」也钳成只降不升**（`mini(cost, X)`）。一行改动，和已定的「减免只降不升」是同一个直觉，玩家不需要记额外规则。**推荐这条。**
- **(b) 保留改写语义**，在 PRD 里明写「『降为』可能抬价，请注意打出顺序」，把它当作顺序博弈的一部分。

### ✅ 定案 A（Kevin 2026-08-30）：选 (b)，卡牌效果改成「将花费**改为** 0.5」

行为不变（抬价保留），措辞改准确。已实装：卡面/日志/常量注释统一为「改为」，
`PRD差异对照.md` 〇.3 的措辞草稿同步修订（「降为 X」→「**改为 X**」，并补一句
「改写可能使数值升高」），草稿里原来那句「卡面文字不用改」**作废**。新增 〇.4 条目
记录这次改字，另建议【上皮—间质转化】一并改称「改为 0.2」（行为零变化，待队友确认）。

## 二、`state_hash` 不认打出先后（高）

### 复现

```
B(先巡航后趋化) 与 C(先趋化后巡航) 移动费相同？   false   （0.5 vs 0.0）
B 与 C 的 state_hash 相同？                    true
```

两个局面的结算结果不同，全状态哈希却完全一样。

### 根因

提交 093c735 把 `cell["play_n"]` / `mods[].seq` / `cell["equip_seq"]` 变成了**规则相关数据**（移动费链靠它排序），但 `cw_game.gd:846` 的哈希拼装没跟上：

```gdscript
for m in cell["mods"]:
    mods.append("%s*%d%s" % [m["name"], m["uses"], m["until"]])   # 没有 seq
```

`equipped` 也只 join 名字。两个数组各自的内部顺序碰巧被数组顺序捎带上了，但**即时卡与永久技能之间的交错顺序**完全没进哈希——而恰恰是这个交错决定了移动费。

### 影响

- 确定性回放校验、将来的联机对局校验会漏判这一类差异
- **快照 / 回滚不受影响**：`snapshot()` 走 `cells.duplicate(true)`，全字段深拷贝，AI 推演是安全的

### 处理建议

纯工程修复，没有规则内容：mods 串补上 `seq`，cell 行补上 `equip_seq` 的排序展开，并加一条断言——「两个只差打出顺序的局面，哈希必须不同」。

## 三、【TGF-β释放】喊出假的「双重触发」（中）

### 复现

打出【TGF-β释放】之后，**下一个世界回合开头**必定出现这一行日志：

```
【双重触发】【TGF-β释放】第二回合再次生效
```

而这一局根本没有抽到过【双重触发】。

### 根因

`cw_world_fx.gd:60`（`on_round_start`）用 `not DURATION.has(name)` 判断「这是个本回合类**世界事件**、只有被双重触发才能活过回合末」：

```gdscript
elif not DURATION.has(e["name"]):
    game.log_msg("【双重触发】【%s】第二回合再次生效" % e["name"])
    await _resolve(e)
```

但 `events["active"]` 这个容器按 #26 的设计**也装卡牌挂上去的全局修饰条目**。【TGF-β释放】正好三条都满足：卡牌挂的、`left=2`（要活到下个 S 阶段的有氧结算）、不在 `DURATION` 表里（那张表只列世界事件）。于是它掉进了这个分支。

`_resolve` 对它是空操作（match 落到 `_: pass`），所以**没有数值影响**，只是日志骗人——而日志是玩家理解结算的唯一窗口。

### 顺带一条：文件头的注释要收紧

`cw_world_fx.gd` 头注写着「**当前排期下两个事件不会同时在场**」。实测容器里可以同时有三条：

```
active 同时在场：基质稳定, TGF-β释放, 基质阻隔
```

那句话只对**世界事件**成立，卡牌挂的条目不受触发排期约束。结论本身没错（各结算点独立查询，重叠也撑得住），但措辞该改成「两个**世界事件**不会同时在场」，免得下一个接手的人据此做简化。

### 处理建议

纯工程修复：给分支加一个「只处理世界事件」的判据（条目建立时打个 `world: true` 标记，或者判 `name in CWWorldFx.EVENTS`），并补一条断言——「打出 TGF-β 之后，下个回合开头不得出现『双重触发』字样」。

## 四、【囊性护甲】挡不住世界事件的能量损失（中）

### 复现

同一个印戒细胞癌、同一轮、护甲都没用过：

```
经 immune_hit（免疫卡牌 1.0）              实际损失 0.5    ← 护甲生效
经 cancer_hit（免疫抑制因子 0.5）          实际损失 0.5    ← 不减免
护甲这一轮是否已被算作用掉                  false          ← 而且根本没触发
```

### 根因

【囊性护甲】的实现只写在 `cw_game.gd:634` 的 `immune_hit` 里。而 `immune_hit` 自己的函数注释（`cw_game.gd:608`）明写：

> attack=false 表示这次损失**不是「攻击」**……而【标记】×2 和【囊性护甲】管的是"损失"，任何来源都生效。

**注释和实现打架。**「任何来源」这句在 `immune_hit` 内部是成立的（攻击和卡牌都吃），但 `cancer_hit` 那条管线里压根没有护甲。

### 波及范围

小。能打到**癌细胞**的 `cancer_hit` 来源目前只有世界事件【免疫抑制因子】的 0.5（`_resolve` 里对全体癌细胞结算）。【增殖抑制】打的是免疫细胞，反弹伤害也是打免疫。所以实际只差这一条通道、每局最多触发一到两次。

但它是**口径不一致**：卡面写的是「受到的能量损失 -0.5」，没有限定来源。

### 处理建议

**要团队定**：【囊性护甲】到底挡不挡世界事件造成的损失？

- 若「挡」：把护甲挪到两条管线共用的位置（或在 `cancer_hit` 里补一份），并同步修正 `immune_hit` 的注释
- 若「不挡」：改卡面/口径措辞，明确写成「受到**免疫方**造成的能量损失 -0.5」，并把 `immune_hit` 那句「任何来源都生效」的注释改掉

### ✅ 定案 B（Kevin 2026-08-30）：挡。卡面改成「每世界回合第一次能量损失 -0.5」

去掉「受到的」，**不限来源**。已实装：抽成 `CWGame.armor_cut()`，`immune_hit` 与
`cancer_hit` 都来这里取减免，**共用同一个每世界回合额度**；`immune_hit` 那句
自相矛盾的注释已改。⏳ 遗留一问：【突变】第 3 面的**自扣** 1.0 不走管线，
目前**不挡**（按口径 #68「自扣不是受到损失」），要不要也挡——待团队确认（清单 F）。

## 五、【抗原呈递强化】目标当场死亡时闸门被白烧（低）

### 复现

树突状细胞装备【抗原呈递强化】，一击打死一个**未被标记**的癌细胞：

```
目标是否已死                              true
【抗原呈递强化】本世界回合闸门是否已烧掉      true    ← 但没有施加任何标记
```

### 根因

`cw_actions.gd:495`：

```gdscript
if game.has_skill(cell, "抗原呈递强化") and not was_marked \
        and game.first_this_round(cell, "抗原呈递强化") and target["alive"]:
```

`and` 从左到右求值，`first_this_round()` 是**有副作用的**（第一次调用即记账），它排在 `target["alive"]` 之前，所以目标死了照样把闸门烧掉。

同一个文件里【抗体亲和力成熟】那处（`cw_actions.gd:410`）把闸门放在条件链**最后**，是正确的写法——所以这里更像是笔误，而不是刻意的设计。

### 处理建议

**要团队定口径**：把目标打死了，算不算用掉了「每世界回合第一次为癌细胞施加标记」的额度？

- 口径 #70 定的是「攻击……后」按**攻击发动**读（判定失败也算攻过）。按这个精神，打死也算「攻过」，烧掉闸门是自洽的——那就把 `target["alive"]` 挪到 `first_this_round` **之前**，让它成为一个**自觉的**选择，并在口径里写明
- 若认为「没有标记可施加就不该扣额度」，同样把 `target["alive"]` 前移即可（结果相反，改动一样）

无论哪种，**当前这个行为是求值顺序的副产品，不是决定**，应当明确下来。另外：闸门烧掉时玩家**零反馈**，日志里什么都没有，建议补一句。

### ✅ 定案 C（Kevin 2026-08-30）：按口径 #70 —— 打死目标也算攻过，额度照烧

行为不变，但从「副产品」变成「明写的选择」：拆成两层判断（闸门在外、`alive` 在内），
并补了日志「【抗原呈递强化】目标已死亡，本世界回合的施加额度就此用掉」。

## 六、组织巡航 + 组织驻留：一次移动烧掉两个「本回合首次」（低）

### 复现

免疫细胞同时装备【组织巡航】（首移免费）与【组织驻留】（本回合首次向健康组织迁移免费），本回合第一次移动到健康组织：

```
首移→健康组织 报价                          0.0
【组织巡航】闸门已烧                          true
【组织驻留】闸门已烧                          true
同回合第二次→健康组织 报价（本可再免费一次）      0.3    ← 只剩巡航的 -0.2
```

一次移动只需要一个免费额度，却把两个都消耗掉了。

### 定性

这和 2026-08-30 已拍板的「【微环境压迫】连带消耗其他护盾是有意为之、这本身就是一种战术」属于同一类。按先例，本条**大概率也应判为有意为之**。

但有两点差异值得单独确认一次：

1. 那次消耗的是两张**一次性护盾**（打出时就知道会一起用掉）；这次消耗的是两个**每回合额度**（玩家会预期它们各自独立）
2. **报价上完全看不出来**——界面显示 0.0，玩家无从得知第二个额度被浪费了

### 处理建议

要团队确认。若维持现状，建议至少在日志里把两条都打出来；若认为该省，则加「已经免费就不再烧下一个闸门」的短路。

### ✅ 定案 D（Kevin 2026-08-30）：**不是**有意为之，要省免费额度

没有为这两张卡开特例，而是定了一条通用判据：**「这一次算出来的价钱和进来时一样
→ 它没起作用 → 额度留着」**。因此顺带也修好了同类的浪费：限次折扣卡
（CXCR3趋化 / 上皮—间质转化）在价钱已踩到下限时不再扣次数，【迁移激活】的
每回合免费额度在价钱已经是 0 时同样保留。已写进 PRD 措辞草稿（〇.3）。

**顺带做了本次最值钱的一笔重构**：把「报价」和「收费」合并成一个函数
`_move_cost_chain(cell, dest, base, commit)`。问题 6 之所以存在，正是因为这两件事
原先是分开写的两份谓词、靠一句注释要求「必须一字不差」。合并之后这一类 bug
在结构上就不可能再出现；`_do_move` 另加一句守卫，兑现价与标价不符就喊出来。

## 七、已验证**无**问题的部分

列出来是为了说明覆盖范围，避免下次重复审：

- **三层结算顺序**（基准价 → 卡牌按打出先后 → 世界事件最后）与给团队的裁定一致：基质阻隔 / 上皮—间质转化 / 伪足穿透 三者关系正确
- **能量损失五步管线**只有 `immune_hit` / `cancer_hit` 两个入口，没有任何地方绕开自己算（唯一的直接扣减是【细胞毒性增强】T 细胞那一笔，卡面明写「不受减伤效果影响」，口径 #67 已定）
- **报价与收费的谓词逐条对得上**：审查时是人工核对 `_move_cost_mod` 与 `_spend_move_mods`
  八张卡/技能（【组织浸润】无闸门无次数、不需要消耗，属正常）；**定案 D 之后两者已合并成
  一个函数**，这一条从此不再需要人工核对
- **同名多条各占一位、各扣一次**，与定案 #57 一致
- **`_cut_cost` 的边界正确**：已经是 0 的价钱不会被减免卡抬回 0.2
- **【抗原丢失】的覆盖面正确**：罩住了普通伤害、【细胞毒性增强】直击、【吞噬体成熟】处决；【补体级联】的组织转化在罩子外（不是能量损失，有意）
- **攻击判定链顺序正确**：骰面 → 世界事件并给 → 补体调理重掷 → PD-L1 压级；【高亲和力克隆】跳过骰面但 PD-L1 照压
- **死亡与快照**：`kill()` 清 mods、`equipped` 不掉、`snapshot()` 全字段深拷贝，回滚安全

## 九、伤害计算流程确认（口径 #78）

Kevin 另问「请确认伤害相关计算流程明确」。全引擎盘点结果：

**只有两个损失入口**，都落在 PRD 五步管线 `CWGame.settle_loss(base, add, mult, div, cut)`
= `max((base + add) × mult ÷ div - cut, 0)` 上：

| 入口 | 来源 | ②固定增加 | ③倍增 | ④倍减 | ⑤固定减免 |
|---|---|---|---|---|---|
| `immune_hit` | 免疫（攻击 / 卡牌 / 抗体 / 细胞毒素） | 攻击类修饰的额外伤害 | 【标记】×2 | 树突【各司其职】÷2（仅普通攻击） | 【囊性护甲】、【DNA损伤修复】（仅非攻击） |
| `cancer_hit` | 癌症技能 / 世界事件 / 压迫 / 反弹 | — | — | — | 【囊性护甲】、【细胞膜修复】、【I型干扰素】、【缺氧适应】、【耗竭抵抗】 |

**绕开管线的只有两处，都是卡面明写的**：

1. 【细胞毒性增强】T 细胞的 +1.0 —— 卡面「不受减伤效果影响」（口径 #67）
2. 【突变】第 3 面的自扣 1.0 —— 自己扣自己，不是「受到损失」（口径 #68，BCL-2 也救不了）

**其余直接写 `energy` 的地方都不是损失**：`pay()` 是费用支付（规则总则把「费用」和
「损失」分开）、`_lose_energy()` 是管线内部的落地、复活/免死/死亡三处是**赋值**。

结论：**没有第五条路，流程明确。** 这个盘点是可复查的——
`grep -rn '\["energy"\] *-=' game/scripts/` 只会出现上面列的那几行。

## 附：复现方法

六条全部用临时探针脚本在引擎里实跑取证（脚本已删）。要重跑的话，在 `game/tests/` 下建一个 `extends SceneTree` 的脚本，用 `CWSetup.make_cell` 造细胞、`CWGame.add_mod` 挂即时卡、手写 `equipped` + `equip_seq` 挂永久技能，然后：

- 问题 1 / 6：调 `game.actions._move_cost_mod(cell, dest, base)` 取报价，再 `await game.actions._do_move(...)` 看消耗
- 问题 2：造两个只差打出顺序的局面，比对 `game.state_hash()`
- 问题 3：`game.install_event("TGF-β释放", 2)` 之后 `await game.world_fx.on_round_start()`，读 `game.logs`
- 问题 4：同一个 SIGNET 细胞先后走 `immune_hit` 与 `cancer_hit`，比对损失
- 问题 5：把 `tune.attack_dmg_success` 调高保证一击必杀，攻击后查 `cell["fx_turn"] / fx_round`

运行：

```
godot --headless --path game --script res://tests/<脚本名>.gd
```
