### 2.1 `WorldState` 要加两个字段

```csharp
// WorldState.cs，与 Effects 并排
public IReadOnlyList<string> EventPool { get; init; } = [.. WorldEffects.WorldEventNames];

```
* `Copy(...)` 补两个可选形参、`CopyWorld` 的字段清单护栏跟着走（迁移计划「共同批 −1」铺的那道反射护栏会当场点名，不会漏）。
* **这是本批唯一一处动 `WorldState`** —— E-4 拍板时明写「不动 `WorldState` / `DecisionRouter` / `MatchSession`」，所以**要 Kevin 一句话**（§6 第 1 条）。
* 替代方案（不推荐）：把 pool 放进 `TurnState`。`TurnState` 是「本回合」的东西，事件池是整局的，放错地方以后每个 `WithTurn` 都要记得抄。

### 2.2 抽取的 rng 次序（带子口径，与 GD `randi_range` 逐笔对齐）

GD `trigger()` 的 rng 消耗**恰好一笔**，且只在 `pool.size() > 1` 时真消耗：

```gdscript
var name: String = pool.pop_at(game.rng.randi_range(0, pool.size() - 1))
```

* `pool.size() == 1` ⇒ `randi_range(0, 0)`，`from == to` ⇒ **带子上零消耗**（`cw_roll_tape.gd` 规矩 1 / `TapeRng.Draw` 同）。
  ⇒ `t_ev_double` / `t_ev_double_instant` 那几条把 `pool` 设成单张，**`rolls` 是空表**，用例最干净。
* C# 对应写法：`var i = rng.NextIntRange(0, s.EventPool.Count);`（半开区间 ⇒ 折成 `Draw(0, Count-1)`，与 GD 逐笔相同）。
  ⚠ **不许**用 `PickRandom(pool, 1)`：它是 pop-loop，抽的次数与区间和 `randi_range` 一样只有一笔，但顺手把池子复制一遍、语义绕远；照抄 GD 那一行最省事也最不会错。
* `_chaos` 每只活细胞消耗一笔 `randi_range(0, dests.size()-1)`（`dests.sort()` 之后，固定候选序）；`_chaos_fallback` 同；`_discard_random` 每张手牌非空的癌细胞一笔。
  ⇒ **【紊乱】与【增殖抑制】的一次性部分是 rng 消耗大户**，第二段要连带子一起对。

### 2.3 `round_effects` / `trigger` / `on_round_start` 挂在哪一步

**E 阶段（第 7 步）** —— 位置已经在 C# 里标好了，把注释换成调用即可：

GD 侧 `cw_world.gd:e_phase` 的序：`_mark_adhesion() → world_fx.round_effects() → world_fx.tick_durations()`，**逐字对上**。

**S 阶段（回合开头）** —— 今天 C# **没有落点**，要往 `BoardRules.Produce` 里插两步：

| | GD `cw_world.gd:round_start` | C# 今天 | 第二段 |

**⚠ P2 录容器草稿时补上的一半（归档时加）**：`trigger` 除了改 `events.*`，还写 `$.g.feed_log` + `$.g.feed_seq`（`CWGame.broadcast_world_event`），而规格 §0.6.2 的全局豁免表**不剥 `feed_log`**、`feed_seq` 同样进对拍 ⇒ C# `WorldEventRules.Trigger` **必须一并产出同一条 feed 条目**（`{card, faction: -1, kind: "world", left, pid: -1, seq}`），否则 4 条容器用例在整集合比下各差两条路径。批 5a 的 card-play-feed-log 是同一个坑。

**⚠ 挂起问题（第二段要拆两刀的理由）**：第 2、3 两步在 GD 里是**协程**——【紊乱】落地走 `enter_tile`（可能追出【净化】连锁 / 抽卡撑爆手牌 / 二选一），【营养输送】的 `on_vessel_pass` 会抽卡。

⇒ **推荐把第二段切成两刀**：
* **刀一（不动编排）**：15 个事件里除【紊乱】之外的 14 个 + 整个容器。这 14 个里唯一会追问的是【营养输送】，而它挂在 `Transport` 里（`ResumeStart` 之后，已有挂起机制）⇒ `Produce` 内部的两步**保证不挂起**，`StartStep` 一格不用加。

### 2.4 `events.active[].data` 的编码（B6）

GD 侧 `data` 今天有**三种**键值形状，不是一种：

| 事件 | 键 | 值 |
|---|---|---|
| 紊乱 | `cell["id"]`（int） | `Vector2i` 原位 |
| 营养输送 / 迁移激活 | `cell["id"]`（int） | `true`（bool） |
| TNF-α局部炎症（卡） | `Vector2i` 格坐标 | `true`（bool） |

**观测协议 §四 已经把这三种都定好了**（`docs/观测协议_v1.md` `events` 行）：「`data` 键统一成字符串（GD 的 Vector2i 键 → `"q,r"`），值 bool → 1/0、坐标 → `{q,r}`」，
GD 编码器 `cw_obs_codec.gd:_effect_data` 三支都实现了。**欠的只有靶场这一侧**：

* GD `cw_world_loader.gd:_load_events` / `_dump_events` 今天把 `data` 原样 `duplicate(true)` ⇒ dump 出来是 GDScript 的 `str(Vector2i)`（`"(0, 1)"`），装回去是字符串键 ⇒ 与生产代码的 `has(Vector2i)` 对不上。这就是 **B6**。
* C# `L0Effect.Data` / `ActiveEffect.Data` 是 `Dictionary<string,int>` ⇒ 装得下 TNF（`"q,r" → 1`）与 bool（`→ 1/0`），**装不下紊乱的坐标值**。

**设计（两段式，与刀一 / 刀二对齐）**：
1. **刀一**：键按「含逗号 ⇒ 坐标 `Vector2i`，否则 ⇒ int cell id」解析（不需要按事件名分表）；值 `1/0 ⇒ bool`。
   C# 侧 `Dictionary<string,int>` 一字不改就够用。合上 B6 的 TNF 档与【营养输送】/【迁移激活】的簿记档。
2. **刀二**：值放宽到联合（int 或 `{q,r}`）以承载紊乱原位。C# 要动 `ActiveEffect.Data` 的值类型 + `ObsEffect` + 协议编码器 ⇒ **要 Kevin**（§6 第 3 条）。
   省事的替代（推荐先问）：紊乱原位**不进 `data`**，改成 `Data` 里存两个 int 键 `"<id>.q"` / `"<id>.r"` —— 零类型改动，但协议 §四 要补一句。

> **B6 本批不做。** 它要同时改 GD 的 loader/dumper 与 C# 的 `L0Effect`，而 P1 / P2 在两台副本上并行 —— 批 3 的 NO-GO 就是这么来的（两台不同补丁的副本合不起来）。整条归第二段第 1 刀的第 1 个提交。
