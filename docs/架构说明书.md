## 项目是什么

《Cell War》桌游（免疫细胞 vs 癌细胞）的电子化新版工程。**规则已修改，从零重建，不继承旧版代码**；引擎 Godot 4（GDScript）。

- 规则原文：`Cell War新版规则.md`（在仓库外，用户本地）
- 旧版 demo（旧规则，可作实现思路参考）：https://github.com/Kevinnb66699/SpringSense-2026-2027-Cell-War

## 核心设计：问答桥

引擎**不知道**谁在做决定。需要玩家抉择时，引擎调 `game.ask(pid, req)` 抛出一个「问题 + 选项列表」，由**桥**（`CWBridge` 子类）返回选中的下标。

```
CWGame ──ask(req)──────> CWBridge ──> 启发式 AI / 将来的 UI / 将来的联机对端
       <──选项下标──
       ──show_roll(…)──> CWBridge ──> 掷骰动画（引擎 await 到播完）
       ──show_result(…)─> CWBridge ──> 一句话通报（不 await，提示自己淡掉）
```

`show_roll()` 是同一条桥上的**单向通知**：引擎先用 `rng` 掷出结果，再把结果送给表现层去演，
并 `await` 到动画播完才继续结算。**表现层无权决定结果**，这是约定 #11。
它**广播给所有桥并按对象去重** —— AI 掷的骰旁观者也得看见，热座共用一个 UI 桥时只演一次。

签名：`show_roll(reason, value, sides, pid, at)`。`at` 是这次掷骰指向的格子
（攻击给目标格，突变/抗体给发动者所在格）—— 骰子要落在棋盘上那一格旁边，
坐标只有引擎知道。`pid` 可用于显示「谁掷的」，**但不用来给骰子染色**：
骰面颜色已经表示结果档位，再叠阵营色会两套语义打架（决策「甲」）。

`show_result(text, at)`（由 `CWGame.announce()` 广播，同样按对象去重）是掷骰的**结算说明**——
"攻击大成功"、"突变：无事发生"。**文字由引擎给**：点数怎么判读是规则，
表现层照着点数自己再判一遍等于把规则抄了第二份，改一处就会对不上。
不 `await`，因为提示自己会淡掉，不该卡住结算。

这样同一套规则代码可以驱动 AI 互搏、人机对战、热座、联机，互不干扰。**新增交互时不要在引擎里直接读 UI，一律走 ask()。**

`req` 的形状：`{ kind, pid, prompt, options: [{label, data}], (tag) }`
`kind` 取值：`setup_place` / `action` / `attack_target` / `differentiate` / `remodel_target` / `revive` / `confirm`

### 表现层 `game/scripts/ui/`

| 文件 | 职责 | 注意事项 |
|---|---|---|
| [board.gd](../game/scripts/ui/board.gd) | 把棋盘画出来；`tile_center()` 轴坐标→像素、`hex_at()` 像素→轴坐标；`set_marks()` 设置格子高亮 | 尺寸与布点**只读 `CWData`**，本层不留第二份坐标（见约定 #10）。要把东西摆到某格上一律走 `tile_center()`；高亮是**淡入淡出 + 同心圆由内向外**揭示的（圆心取这批格子的重心）；`set_marks()` 每帧都会被调用，所以目标没变时必须什么都不做（节点要复用，否则补间永远走不完）。**深度一律走 `tile_z(格, above)`**（`tile_center()` 是顶面中心、比贴图中心高 4px，拿它当 z 用东西会掉到棋盘后面——骰子踩过）；点选一律走 `hex_at()` |
| [cw_view.gd](../game/scripts/ui/cw_view.gd) | 机位：菜单/对局两组参数、「看点→锚点→zoom」的反解、两组之间的插值 `blend()` | 全工程只有一台相机，两组参数**必须摆在一起**——开局过场就是在它们之间插值。对局机位 zoom 1.45 / 锚点 (348,270) 与右侧竖条 264px 是同一套推导。**过场插的是取景参数、zoom 走几何插值**——直接插 `camera.position` 会两端都对、中间取景游走 |
| [main.gd](../game/scripts/ui/main.gd) | 入口协调：主菜单 →「开始对局」→ 开场三拍 → 交还控制权；暂停菜单的「返回主菜单」 | 过场时长常量**集中在这里**，别散进各个 Tween。**Control 的 `gui_input` 不会自动吃掉事件**：菜单项点击必须 `set_input_as_handled()`，否则那一下会漏到这里被当成「点一下跳过」，过场整个消失。相机与绽开是两段**前后相接**的动画，绝不能挂同一条时间轴（会把绽开整段跳掉，见开发日志） |
| [match.gd](../game/scripts/ui/match.gd) | 一局对局的装配与呈现：建引擎、注册桥、把状态画到棋盘上、演开场绽开 | 规则一行都不在这里。呈现是**每帧全量刷新**（`set_tissue()` 贴图没变即返回），所以画面不可能和状态对不上 |
| [ui_bridge.gd](../game/scripts/ui/ui_bridge.gd) | 表现层的询问桥：人类玩家的询问界面 + 掷骰演出 | **继承启发式 AI**：同一个对象注册给所有玩家，人类走界面、其余走 AI，演出按对象去重只演一遍。询问界面只有一条规则：选项 `data` 里**带 `to` 就进棋盘、不带就进按钮**，六种询问全覆盖。「迁移」是两段式（先点技能再点格子）且**切换式**——走完一步继续停在选目标格上，退出条件只有「主动退出 / 没有可达格 / 换人或换世界回合」（开关记着 pid + round_no）。引擎那边一步没动，是桥记住了上一次选的是迁移 |
| [action_bar.gd](../game/scripts/ui/action_bar.gd) | 底部行动栏：技能按钮 / 目标选择提示，两种形态照搬定稿 | 只有一个出口信号 `chosen(下标)`；取消不另设信号，它就是 `cancel_index` 指的那个按钮。**数字键 1..9 = 从左到右第几个按钮**（只在技能栏形态生效，数字垫灰底标在费用行前）。⚠ **横向余量很小**：最挤的 T细胞四技能占 346 / 361，加长任何标题或费用文字都可能顶出画布——`t_action_bar_width` 盯着这条。**不传 `cancel_index` 就表示这一问不能取消**，右键与 Esc 一律不响应（否则「选分化方向」时 Esc 会替玩家选中最后一项） |
| [hand.gd](../game/scripts/ui/hand.gd) | 左下角手牌抽屉：叠放、悬停抬起推开、抽卡飞入 | **一张卡同时只能有一条补间**：位置一律由 `_layout()` 统一算，`sync()` 只摆起点。两条补间同改 `position` 会「先瞬间到位再闪回去重播」 | 几个数互相咬死：`卡宽72 − 露出52 = 推开20`、`514 − 抬起86 + 112 = 540`。**间距随张数压缩**——固定 52 的话第 6 张就盖到行动栏上（手牌上限规则未定） |
| [toast.gd](../game/scripts/ui/toast.gd) | 骰子旁边那行字：掷骰时报「攻击/突变/抗体」，停稳后换成结算说明 | 文字一律由引擎给（`show_result`）。位置跟着骰子走——骰子刻意落在棋盘格上就是为了把「谁在打谁」和「结果」绑死，说明不能丢回屏幕角落 |
| [pause_menu.gd](../game/scripts/ui/pause_menu.gd) | 对局中的暂停菜单（Esc）：主列表 / 确认页两页，选中项带辉光 | **不属于左侧「面板槽」**，那是开局前的语法；这是覆盖层。暂停时 `get_tree().paused = true`（AI 间隔是 SceneTreeTimer，会跟着停），自身须为 `PROCESS_MODE_ALWAYS`。Esc 归属靠 `CWActionBar.can_cancel()` 判断，两边各自判断、不依赖事件传播顺序。「返回主菜单 / 退出游戏」要过确认页，且**默认停在「取消」上** |
| [match_panel.gd](../game/scripts/ui/match_panel.gd) | 右侧竖条：回合/阶段、胜负进度、玩家列表、免疫等级、钉底的「结束回合」 | 尺寸照搬定稿标注稿，**一个数都别改**：52 / 56 / 44×人数 / 44 / 52，6 人局合计 530 只余 10px——这套高度是按最挤的情况配平的。宽度必须与 `CWView.PANEL_WIDTH` 一致 |
| [cancer_blob.gd](../game/scripts/ui/cancer_blob.gd) | 癌细胞占位图形（棋盘与玩家列表共用） | 美术到位后整个文件删掉 |
| [cw_style.gd](../game/scripts/ui/cw_style.gd) | 配色、字号、描边框，全工程一处 | 改配色改字号只改这里。字号只有 30/20/10 三档（点阵网格，见约定 #13）。`box()` 的 `pad` 不传就是 0，描边会贴着字 |
| [main_menu.gd](../game/scripts/ui/main_menu.gd) | 主菜单：摆机位、摆装饰细胞、菜单项的选中/悬停/键鼠交互 | 构图照搬定稿原型，机位参数在 `CWView`。装饰细胞的格子坐标一律走 `board.tile_center()` | 
| [dice.gd](../game/scripts/ui/dice.gd) | 掷骰演出（方案 D）。`play()` 是协程，动画播完才返回；`place_at()` 把它摆到棋盘某格上 | 结果由引擎传入，本层只负责演到那一面（见约定 #11）。翻滚随机用节点自己的 `randf()`，**不碰 `game.rng`**。按落地点 y 参与深度排序，与组织块同规则 |

## 关键约定（改代码前必读）

1. **能量用「十分能量」整数存储**：`30` = 3.0 能量。避免浮点误差，保证回放/联机确定性。显示用 `CWData.fmt()`。
2. **所有随机数必须走 `game.rng`**。用了别的随机源，确定性测试（同种子两局哈希一致）会立刻抓到。
3. **不要给 `CWGame` 加名为 `log` 的方法**——GDScript 的内置数学函数 `log()` 不能被覆盖，会导致整个类编译失败。日志方法叫 `log_msg()`。
4. **新增 `class_name` 脚本后必须先 `--import` 再跑测试**，否则报 "Identifier not declared"。
5. **进入一格的所有效果都在 `CWActions.enter_tile()` 里**（定殖/净化/特殊组织收取/标记刷新）。移动、血管传送、复活落位共用它——加新效果加在这一处，不要散落各处。
6. **新增规则状态字段时，要同步更新 `CWGame.state_hash()`**，否则确定性测试会漏检。
7. **平衡数值改动走 `CWTuning`**，不要直接改 `CWData` 常量——`CWData` 是规则原文的记录。
8. **不要在代码或测试里写死棋盘尺寸**（`61`/`127`/`41`……）。一律引用 `CWData.TOTAL_TILES`、
   `CWData.BOARD_RADIUS`、`CWData.CANCER_WIN_WEIGHTED` 等常量。2026-08-27 从 61 格换到 127 格时，
   4 处写死的数字全部变成了假失败，排查成本远高于一开始就引用常量。
9. **改棋盘尺寸后必须重跑平衡**：收入公式挂钩「健康组织格数」，棋盘面积一变，
   低保/封顶的相对位置就全变了——61 格调好的数值搬到 127 格会让癌胜率从 51% 掉到 10%。
10. **表现层不许自己存一份棋盘坐标**。规则层用轴坐标 `(q,r)`，渲染层用「行,列」下标，
    两套坐标之间只有 `board.gd` 的 `axial_to_rc()` 一个转换点，源头永远是 `CWData`。
    2026-08-27 合并渲染代码前，渲染层自己抄了一份特殊组织下标，地图改到第三版时没跟上——
    画出来还是 5 个骨髓、代谢核心还在半径 4。`headless_test.gd` 的 `t_board_view()` 专门防这个。
11. **表现层不许决定结果**。所有随机由引擎的 `rng` 先掷出，再经 `CWBridge.show_roll()`
    送给表现层去演；动画只能演到那个数上，不能反过来决定它。
    掷骰动画的翻滚随机走节点自己的 `randf()`，**绝不碰 `game.rng`**。
    `headless_test.gd` 的 `t_roll_hook()` 会把钩子收到的点数和日志里实际结算用的点数逐次交叉核对。
12. **界面的设计分辨率是 960×540，不要改**。它和界面原型的画布同尺寸，
    原型里的 `1cqw` 正好换算成 `9.6px`，所有定稿坐标能直接乘过来；
    而且 1080p 全屏恰好是整数 2 倍，点阵字和像素贴图都能整数放大不糊。
    拉伸模式是 `canvas_items` + `keep`。
13. **点阵字号只能取字体网格的整数倍**：中文（缝合像素 10px）取 10 / 20 / 30 / 40，
    Logo 用的 Silkscreen 取 8 的倍数。取别的值会被重采样磨出灰边。
    同理，20px 字号下 1 个字模像素 = 2 屏幕像素，**字间距和位移也要取 2 的倍数**。
    `headless_test.gd` 的 `t_main_menu()` 会扫描场景里所有 Label 盯住这一条。
14. **要不要给某个随机加动画，是纯表现层决定**。静默用 `roll_d6()/roll_d3()`，
    带演出用 `roll_shown(sides, reason, pid)`；两者消耗的 rng 完全相同，可随时互换，
    不影响同种子可复现。**不要为了加动画去改 `roll_d6/roll_d3` 的签名** ——
    GDScript 的 `await` 会沿调用链往上传染，那样每个既有调用点都得跟着改。


## 关键决策记录

决策的时间线见 [开发日志](开发日志.md)；本节只保留「现在为什么是这样」的最终结论。

- **引擎与 UI 用问答桥解耦**：旧版验证过的架构，同一套规则可驱动 AI/人机/联机。
- **平衡数值抽成 CWTuning 旋钮**：规则平衡有大量未定项，需要不改代码就能批量试方案。默认值保持规则原文，让「按规则跑」永远是一行代码的事。
- **规则歧义处一律先拍临时决策、记进文档再实现**：见 [规则电子化说明](规则电子化说明.md)，每条都标了待团队确认。
- **确定性优先**：所有随机走 `game.rng` + `state_hash()` + 同种子重放测试。这是将来做联机（确定性锁步）和 AI 模拟打分的前提，代价很小但补不回来。
