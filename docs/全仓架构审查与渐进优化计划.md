# Cell War 全仓架构审查与渐进优化计划

  ## 摘要

  以 origin/main（当前 23d71eb）为基线，在独立 worktree 中实施，不触碰现有未提交改动。保持规则和存档格式兼容，优先修复状态一致性与组织状态 bug，再处理 MC 响应时间和确定存在的重
  复代码。

  最终产出：

  - 更新后的架构说明书与模块关系图。
  - 一份带严重级别、代码证据和处理状态的架构审查报告。
  - 全状态哈希、组织转换、存档校验和 MC 性能的回归守护。
  - 多批次、可独立验证和提交的改动。

  ## 接口与架构调整

  - 新增 CWTissue：统一 to_healthy、to_necrotic、to_cancer、to_solid、crack_to_cancer，禁止业务模块直接写组织类型及关联字段。
  - 新增 CWStateCodec：生成规范化规则状态和哈希；CWGame.snapshot()、restore()、state_hash() 的现有签名保持不变。
  - 新增 CWTuning.signature()，使规则旋钮差异能参与状态校验。
  - CWMonteCarloBridge 增加确定性的 max_sim_steps 和只读 last_stats；0 保持现有无限工作量行为，UI 的“较强 AI”使用固定预算。
  - CWSave 增加 can_continue()；exists() 仍只表示物理文件存在，主菜单改用完整校验结果。
  - 新增 CWStyle.clickable_label()，替代配置页和设置页完全重复的 _clicky()。

  ## 分批实施

  ### 批次 0：隔离基线与建立审查台账

  - 从 origin/main 创建独立 worktree；当前固定有氧、试玩协议和文档改动保持原样。
  - 建立 docs/架构审查_2026-09-02.md，记录实际依赖链：UI/AI → Bridge → CWGame → 流程模块 → 费用/伤害/组织状态。
  - 校正文档已确认漂移：当前测试数、6 人初始癌区 24、实际测试工具清单、MC 基准的日期与硬件信息。
  - 增加 Windows 测试入口，与现有 shell 入口统一检查退出码、断言失败、SCRIPT ERROR 和脚本未加载假通过。
  - 用沙箱外 Godot 跑一次干净基线；资源泄漏用 --verbose 归因，修复项目持有的节点/桥循环，第三方或引擎级警告只记录证据。

  ### 批次 1：补全状态一致性与存档守护

  - 将哈希输入集中到 CWStateCodec，纳入 RNG、flow、待决问题的规则数据、当前玩家、全局分化占用、事件池，以及所有影响后续结算的细胞闸门和次数字段。
  - 明确排除日志、提示文本、桥对象和 play_n 等不改变规则结果的表现或单调计数。
  - 对嵌套字典和数组做稳定排序，避免遍历顺序造成伪差异。
  - 为每个规则字段添加“只改这一位，哈希必须变化”的表驱动测试；验证日志变化不改哈希、快照恢复连 RNG 与流程位置一起还原。
  - CWSave.can_continue() 完整验证版本、人数、快照结构；损坏存档不再让“继续对局”亮起后无响应。
  - 保持存档载荷形状兼容，不升级存档版本。

  ### 批次 2：统一组织状态转换并修复非法组合

  - 用 CWTissue 替换 cw_actions、cw_world、cw_card_fx、cw_game、cw_setup 中的直接组织写入。
  - 固化不变量：
      - 癌组织和固化癌组织的 necrosis 必须为 0。
      - 健康组织的 solid=0、newborn=false。
      - 普通癌组织转换显式声明是否为本回合新生。
      - 特殊组织库存和黏液标记不被无关转换误清除。

  - 修复侵蚀、增生和卡牌转化坏死健康格后仍残留坏死计数的问题，确保结算屏不会把癌组织同时统计成坏死。
  - 删除两份 _to_cancer/_to_healthy 和 _adjacent_healthy_tile 之类的冗余包装。
  - 为侵蚀、增生、放疗、基质重塑、复活和进入格子分别增加转换回归及全盘不变量扫描。

  - 扩展 bench_mc.gd，输出每次决策的候选数、快照数、模拟步数、耗时和阶段，并覆盖固定种子的早/中/晚局面。
  - 采用确定性的模拟步数预算，不使用墙钟超时参与决策，保持同种子同答案。
  - AI 行为版本升号，记录新旧预算、响应时间和固定种子选择差异；跑 2/4/6 人浅层 MC 冒烟对照，性能批次不顺带调平衡数值。

  ### 批次 4：低风险去重与职责收口

  - 把配置页、设置页重复的可点击文本构造收进 CWStyle.clickable_label()，保留各页面自己的焦点和布局逻辑。
  - 对全部函数做引用复核，只删除有测试覆盖且确认无动态调用的包装函数；不因文件超过千行就机械拆分。
  - cw_card_fx.gd 保持卡牌效果总入口，因为按效果族集中仍具备内聚性；组织转换和状态编码移出后重新评估，只有出现独立生命周期或明确依赖边界才再拆模块。
  - 检查每帧 UI 刷新，保留已有的“值未变即返回”；除非剖析显示帧耗时异常，不引入复杂脏标记系统。

  ### 批次 5：文档收口与全量验收

  - 更新 docs/架构说明书.md：模块所有权、状态哈希边界、组织转换 API、MC 两种预算模式、准确测试清单和最新实测数据。
  - 在每个有架构变化的批次同步追加 docs/开发日志.md，记录改动原因和取舍。
  - 审查报告逐项标记“已修复、保留设计、后续事项”，避免与权威架构说明重复维护现状。
  - 沙箱外执行全量无头测试、协议测试、MC 基准和一轮启动/拆局烟测；要求断言全绿、无 SCRIPT ERROR、无项目自身资源泄漏、同种子结果一致。

  ## 重点测试场景

  - 相同盘面但 RNG、流程阶段、待决玩家、分化状态或技能次数不同，哈希必须不同。
  - 添加并消耗修饰后仅剩无语义的 play_n 差异，哈希仍应还原。
  - 坏死健康格经侵蚀、增生或卡牌转癌后，坏死清零且结算统计正确。
  - 快照推演和 MC 决策不污染真实桥、日志、RNG、事件池或行动次数。
  - 损坏、截断、旧版本存档不会亮起“继续对局”，合法 v1 存档仍可恢复。
  - MC 固定种子在不同机器速度下选择相同，代表性决策 P95 达到 500 ms 目标。
  - 配置页和设置页抽取公共构件后，键盘、鼠标、辉光、箭头和即时保存行为不变。

  ## 假设与边界

  - 本轮不修改 PRD 规则和平衡数值，不实现联机功能，也不替换现有字典状态模型。
  - 当前工作树中的固定有氧实验不纳入主线修改；最终提供其与新分支的冲突清单。已知需要重新处理的区域包括 cw_tuning.gd、cw_world.gd、相关测试、平衡参数和架构文档。
  - 合并固定有氧实验时必须删除或迁移已失效的 amult/agrow 参数，并重新跑全量测试；该合并由后续单独批次完成。
