## 一、目标与范围

**目标**：让玩家在不同地方、不同局域网下，用各自的电脑打同一局 Cell War；规则、骰子、抽卡、判定与本地人机完全一致。

v1 做：
- 昵称 + 房间码建房/加入；房间可设**公开**（进大厅列表）或**私密**（只凭房间码）。
- 等待室：2 / 4 / 6 人局，自己点空席坐下（席位 = 阵营 + 出手顺序），可换席；房主给空席放 AI（新手 = 启发式，专家 = 蒙特卡洛）；全员准备后房主开局。
- 对局：沿用现有对局界面；每次决策有回合计时（建房选项，默认 60 秒）；每个客户端只看到自己视角（别人的手牌只有张数）。
- 掉线：席位保留，凭令牌重连从当前状态继续；超时未回由 AI 代打直到回来。
- 结算：沿用现有结算屏，然后回到等待室可再开一局。
- 服务器发版：**排空后重启**（维护中不许建新房，现有对局打完自动切新版）。
- 客户端：测试阶段从仓库跑；正式用 Windows / macOS 导出包；版本不符的客户端进不来并提示更新。

v1 不做（团队 2026-09-02 定）：观战、房内聊天、回放与战绩、排行榜、账号系统、热座（同机两人）+ 远端混合、网页版。

## 三、服务器实测（2026-09-02）

服务器：腾讯云 Ubuntu 22.04，4 核 / 3.7 GB / 28 GB 空闲盘，上面还跑着 nginx、ielts、PostgreSQL、pm2；8611 空闲；SSH 用专用钥匙 `~/.ssh/cellwar_ed25519`（别名 `cellwar`）。测试时 Godot 进程降了优先级（nice 10），负载峰值 1.6，其它服务不受影响。

| 项目 | 服务器（4 核） | 笔记本（同时跑满平衡网格） |
|---|---|---|
| 专家档 MC 单步决策（rollouts=2 · horizon=40 · 8 个候选） | 381 ms | 645 ms |
| 专家档 2 人整局（一个 MC 席，11 回合） | 33.6 s | 54.4 s |
| 标尺档 6 人整局、6 席全 MC（同种子 101） | 30.2 s（同时还跑着 3 局） | 39.4 s |
| 启发式 6 人整局（含全部规则结算） | 0.3 s / 局 | — |
| 4 局同时跑 | 与单跑一样快，4 核不打折 | — |
| 单个无头 Godot 进程内存 | 123 MB | — |

读法：真人对局的规则结算每步不到 1 ms；AI 补位每次决策 0.1～0.4 s，每回合每个 AI 席 1～2 s；真人每步几十秒。**一个房间平均只占一个核的 1～3%**。瓶颈是内存，所以所有房间跑在同一个进程里（每局状态不到 1 MB），不做一房一进程。平衡网格那种上千局 MC 互搏才吃 CPU，不放这台机器。

## 四、总体架构

```
客户端（Godot，Windows/macOS）                 服务器（同一份工程，无头 Godot，systemd 常驻）
┌──────────────────────────────┐  ws://124.221.78.13:8611  ┌────────────────────────────────┐
│ 主菜单 → 联机面板（昵称/地址）│ ◄───────────────────────► │ CWNetServer：连接、握手、版本校验 │
│   → 大厅（公开房列表/建房/输码）│                          │   ├ 大厅：房间列表、建房、加入      │
│   → 等待室（席位/AI/计时/准备）│                          │   └ CWRoom × N：席位、状态机       │
│   → 对局（现有 MatchView）    │                          │       ├ CWGame（规则、骰子、抽卡）  │
│      影子 CWGame ← 视角快照    │                          │       ├ CWNetBridge（真人席）       │
│      CWUIBridge ← ask/roll/… │                          │       ├ CWHeuristic/MC 桥（AI 席） │
│   → 结算屏 → 回等待室         │                          │       └ 每客户端一份视角快照        │
└──────────────────────────────┘                          └────────────────────────────────┘
```

接缝就是现有的桥接口：引擎问玩家决策走 `CWBridge.ask(req) -> int`（`req = {kind, pid, prompt, options}`，答案是下标），演出走 `show_roll / show_result / show_notice`。

- **服务器**：真人席挂 `CWNetBridge`，`ask()` 把 `req` 发给该席位的客户端、等答案或超时；AI 席直接挂现有 AI 桥。引擎每 `step()` 后给房内每个客户端发一份**视角快照**。
- **客户端**：本地放一个**影子 `CWGame`**，收到快照就 `restore()`，现有棋盘/面板/日志照常从它读；收到 `ask` 就调现有 `CWUIBridge.ask(req)`，把下标发回去。演出消息（骰子、结果、通报）排队按序播放，播完再处理下一条，避免服务器已经走到下一步而本地动画还没演完。
- 视角快照 = `snapshot()` 去掉 `rng`，别人的 `hand` 换成同长度的占位（界面只显示张数），对局日志里**别人抽到的牌名**改成「抽了一张牌」（核心 `log_msg` 加一个「只对某席可见」标记，改动 3 处）。

## 五、协议（草案）

握手：客户端 `hello {ver, nick, token?}` → 服务器 `welcome {client_id, ver}` 或 `error {code: "version", server_ver}`。`ver` 是仓库里的 `NET_VERSION` 常量，协议或规则变了就升号；不符即拒绝。

| 方向 | 消息 | 内容 |
|---|---|---|
| C→S | `list_rooms` | 公开且在等待中的房间 |
| C→S | `create_room` | `{players: 2/4/6, timer: 30/60/90/0, public: bool}` |
| C→S | `join_room` / `leave_room` | `{code}` |
| C→S | `sit {seat}` / `stand` / `ready {bool}` | 席位 = `game.order` 的下标 |
| C→S（房主） | `set_ai {seat, tier: "heur"/"mc"/null}` / `kick {seat}` / `start` | |
| C→S | `answer {ask_id, index}` | 对某次询问的回答 |
| C→S | `reconnect {code, token}` | 掉线后重入 |
| S→C | `lobby {rooms}` / `room {code, public, timer, seats[], host, state}` | 等待室全量状态 |
| S→C | `state {view, hash_public}` | 视角快照；`hash_public` 用于测试对账 |
| S→C | `ask {ask_id, req, deadline_ms}` | 只发给该席位；重连时重发（剩余时间照旧） |
| S→C | `roll {…}` / `result {text, at}` / `notice {text}` | 对应桥的三种演出 |
| S→C | `game_over {winner, reason, kind}` | 之后房间回到等待中 |
| S→C | `maintenance {bool}` / `error {code, msg}` | 排空提示、通用错误 |

限制：单条消息 ≤ 64 KB、每连接每秒 ≤ 20 条、每 IP ≤ 8 连接；房间码 6 位（去掉 0/O/1/I 的 32 字母表）。

## 六、房间与对局规则

- 建房者是房主；房主在等待室离开则房主转给下一位坐着的真人；空房 10 分钟自动关。
- 开局条件：每个席位有人或有 AI、真人 ≥ 1、真人全部准备。种子由服务器随机（测试可指定）。
- 对局中离开或掉线：席位标「离线」，**立刻**由启发式代打当前询问之后的决策；令牌到本局结束前有效，重连即接管。
- 回合计时：按**每次询问**计时；到点服务器按启发式建议作答；客户端显示倒计时（服务器给的 `deadline_ms` 换算）。
- 局末：全员收到 `game_over` 与结算数据，房间回到等待中、席位保留，房主可再开一局。

## 七、客户端改动

- 主菜单加「联机」入口 → 联机面板（昵称、服务器地址默认 `124.221.78.13:8611` 可改，方便内网自测）→ 大厅 → 等待室 → 对局 → 结算 → 等待室。
- `match.gd` 加「联机模式」：不 `new CWGame` 跑 `run_game()`，而是挂 `CWNetClient`，桥仍是 `CWUIBridge`（`human_pids = [自己的席位]`），演出与询问由网络驱动。
- 对局内加：倒计时、每席位的「离线 / AI 代打中」标记、断线时的「重连中」遮罩、暂停菜单只留「离开房间」；联机局不写本地存档。
- 界面三张图（联机面板、大厅、等待室）开工前出 Godot 实机预览给团队看。

## 八、服务器端与部署

- 代码与客户端同一仓库：`game/scripts/net/`（协议、服务器、房间、网络桥、客户端）+ `game/server/server_main.gd`（`extends SceneTree` 入口）。启动：`godot --headless --path game --script res://server/server_main.gd -- port=8611`。
- 服务器目录 `~/cellwar/`：Godot 4.5 Linux 二进制、`game/` 工程副本、`run.sh`、`DRAIN` 标记文件；systemd 服务 `cellwar.service`（`User=ubuntu`、`Restart=always`、日志进 journald）。不碰机器上其它项目。
- 发版：`tools/deploy_server.sh` 把 `game/` 打包传到 `~/cellwar/next/` 并写 `DRAIN`；服务器进入维护中（拒绝建房、大厅出横幅），最后一局打完自动退出；systemd 重启前把 `next/` 换成 `game/`。没在打的局就立即重启。
- 单线程：AI 决策期间同进程其它房间会停顿（常见 0.1～0.4 s，专家档候选多时 1～2 s），v1 接受；以后需要再把 AI 决策丢到工作线程。

## 九、隐私与安全

- 无账号、无密码；昵称不唯一。服务器只存房间与对局的内存状态，不落盘、不记录 IP 以外的任何个人信息。
- 客户端拿不到 `rng` 状态与他人手牌，改客户端也算不出下一张牌；所有规则判定在服务器。
- 8611 明文 `ws://`（对局数据不敏感）；将来若做网页版再经 nginx 上 `wss://`。
