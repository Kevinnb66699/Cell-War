# 临时下架清单

**这份文档的用途：把「先关掉」的功能怎么关的、关在哪、怎么开回来，写在一处。**
2026-09-10 Kevin 连着拍板下架三样，一样一个开关。开回来时照着这份走，不必满仓库找。

三个开关全在 **`game/scripts/ui/match.gd` 文件顶部**（`CWMatch` 的常量区）：

```gdscript
const CHAT_ON := false     ## 房内聊天
const REPLAY_ON := false   ## 看回放
const WATCH_ON := false    ## 观战
```

## 三条共同的纪律

1. **只关「界面上有没有入口」，一点底层都不动。** 类还在、协议一个字没改、
   服务器那半边照常收发、回放照常录照常存盘。所以开回来那天：
   **不用补数据、不用改协议、不用重新部署服务器。**
2. **护栏测试照常跑。** 每个功能自己那几条测试（`t_chat_box` / `t_replay` /
   `t_replay_panel` / `t_net_watch` / `t_net_chat` / `t_net_replay_download`）
   一条都没删 —— 开回来那天不用从头验一遍。
   而跟「入口在不在」有关的断言都写成了 `== CWMatch.XXX_ON`，
   **改开关不用改测试**，套件自己跟着走。
3. **改这三行要连着改这份文档。** 否则下一个人只能靠 grep 猜。

---

## ① 房内聊天　`CHAT_ON`

**为什么关**：Kevin 2026-09-10 实战报了三条，都在「开着就会误操作」这一档。

**触点**（`CHAT_ON` 为 false 时）：

| 位置 | 关掉之后 |
|---|---|
| `match.gd::_wire_bridge` | 不建 `CWChatBox`，`_chat` 恒为 null |
| `match.gd::_unhandled_input` / `_toggle_chat` / `_sync_chat` | 本来就按 `_chat == null` 兜底，自动不响应 |
| `log_hint.gd` | 没人调 `set_chat()`，迷你条那页「聊天」`visible = false` |

**不受影响**：等待室那份聊天（`CWOnlinePanel` 右栏）照常 —— 那儿没有棋盘快捷键要抢。

**开回来之前要修的三条**：

1. **从迷你条点开之后关不掉。** 展开的框 340×460 正好盖住迷你条自己那个「聊天」页
   （两者共用左上角 `CWLogPanel.RECT`），而标题写着的「Enter 收起」在框开着时
   被输入框吃掉了（`text_submitted` 收到空串 = 什么都不做）。
   → 至少要让 Enter 在空串时收起框，或者把收起入口挪到框自己身上。
2. **点框外空白处该收起。** `CWLogPanel` 早就是这么做的（`_unhandled_input` 里，
   并吃掉那一下），这份漏了。
3. **打字打到 L 会弹出对局日志。** `CWLogPanel._unhandled_input` 的单键快捷键
   没有「玩家正在打字」这道闸。**空格 / 方向键多半同病**，要一并按焦点判 ——
   建议加一条共用判据（焦点落在 `LineEdit` / `TextEdit` 上就让路），
   而不是在 L 那一处补一个 if。

**已经做好、随开关一起先不露面的**：Tab 换「全体 / 己方」（Kevin 2026-09-10 要的）。
它必须在**输入框自己那一层** `accept_event()` 截 —— `ui_focus_next` 就绑在 Tab 上，
Godot 的焦点导航排在 `_unhandled_input` 前面，不截就被拿去切焦点、输入框还丢焦点。
护栏在 `t_chat_box`。

## ② 看回放　`REPLAY_ON`

**为什么关**：Kevin 2026-09-10 拍板，和聊天一起先收。

**触点**：

| 位置 | 关掉之后 |
|---|---|
| `main_menu.gd::_item_enabled` | 主菜单「对局回放」**灰着**（不是抽掉：八项的位置是场景里钉死的，抽掉会在中间留个洞；灰着还顺带告诉玩家「这功能在，只是这一版先不开」） |
| `settle_screen.gd::_build_buttons` | 结算屏「看这局回放」那条链接**不建** |

**录制不停。** `CWMatch.start()` 里的 `game.record_replay = true` 照常，
服务器的回放柜（`CWNetServer.keep_replay`，留最近 50 局）也照常存盘 ——
**关着这段时间打的局，开回来之后还看得到**。

**开回来只需把开关改 true**：`CWReplayPanel`、`CWReplay.Player`、播放条、
键盘播放控制、从服务器下载回放，全都原封不动。

## ③ 观战　`WATCH_ON`

**为什么关**：同上。

**触点**：只有一处 —— `online_panel.gd::_on_message` 的 `"lobby"` 分支：

```gdscript
_lobby_live = m.get("live", []) if CWMatch.WATCH_ON else []
```

**收在这一处就够**：`live` 空了，`_compose_lobby()` 连「进行中 · 可观战」那条
小标题都不会摆，也就没有行可选、没有行可点。
服务器照常在 lobby 报文里带 `live`，**协议一个字没改**。

**没关的**：房间里「未入座」的人（那是等待室的概念，不是观战一局进行中的对局）、
协议里的 `watch` 报文、服务器的观众席与 `CWRoom.MAX_WATCHERS`。

---

## 开回来的做法

1. 把要开的那一行改成 `true`。
2. `bash tools/run_tests.sh` —— 断言写的是 `== CWMatch.XXX_ON`，会自动切到
   「开着该怎样」那一档。**红了就是真有问题**，不是测试没跟上。
3. 聊天要先修上面那三条，否则开回来还是那三个毛病。
4. 回来之后把这份文档里对应那一节删掉，并在 `docs/开发日志.md` 记一笔。
