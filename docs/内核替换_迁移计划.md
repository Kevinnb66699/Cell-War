## 〇、一页结论：这是一次几个月的工程，不是几周

**把七路各自的估算相加 = 125~199 人天**，而**没有一路写下这个数** ——
每一路只看自己那一段，于是「合计」这件事在七份文档里都不存在。

再加上三路复核补出来的、**七路集体漏掉的账**：

| 漏项 | 估 | 为什么漏了 |
|---|---|---|
| **15 个世界事件在 C# 里一个都没有** | 3~6 人天 | `cw_world_fx.gd` 363 行 / `const EVENTS` 15 条，逐名 grep C# 侧 **15 个全 0 命中**。规则缺口那一路只买了「容器」，没买内容 |
| **三个接线点无人认领** | 10~19 人天 | `ui/match.gd` 2035 行（09-18 数；写这段时是 2021）、`cw_replay.gd` 313 + `replay_panel.gd` 467、`guide_director.gd` 117 + guide 800 行。**「教程放最后」不等于「教程免费」** |

| **切换当天（cutover）** | 3~5 人天 | 零预算。影子并跑多久、go/no-go 判据、回滚怎么回，没有一路写 |

| **平衡重标定** | 1~2 人天 + 机时 | 不是「万一」是**必然**：9 张单位错位卡改完强度 ×10、无氧 k 补全、增生改整数千分位、AI 整个重写 —— 每一条单独就能让标尺作废 |
| **迁移期双修** | 未估 | 决策 8 让 main 继续维护。`git log --since=2026-09-08 -- game/scripts/core/` = **+2192/−720，71 个提交**（≈310 行/天）。移植期内 main 还会新增数千行规则，**全部要再移植一遍** |

⇒ 复核给的量级是 **5~8 个月、两人并行**。

### ⚠ 但这些数今天都不能当承诺用，原因要说清楚

**「人天」这个单位没有任何一路定义过**，而两个仓库里就摆着现成的速度锚点、无人引用：

* 本仓：21 个日历日、559 提交，`core/` +12733/−3229、`tests/` +28436/−3687，同期还产出 19192 行 UI
* 队友仓：**3 个日历日**、33 提交，产出 5296 行 C# 内核 + 2715 行测试

照后者算，各路的编码估算比本项目实测速度**慢 6~20 倍**。
两种解释都成立 —— 要么「人天」是另一种单位，要么**历史速度在「必须与一份 3502 项检查的参考实现等价」这个约束下根本不可复现**。
我倾向后者（这正是 triage 那 10~20 人天要买的东西），但**没有证据判定**。

**所以这份计划给的是顺序和依赖，不是日期。** 要日期，得先跑完 M0 拿一个真实速度点。

### 另外两条不可引用的数

* **性能**：两路给了互相矛盾的实测 —— 一路说 C# 比 GDScript **慢 34%**，另一路说 C# **快 2~3 倍**。
  同一对引擎、数字差 1.7~2.2 倍、结论相反。**两条都不能用**，要给性能结论必须先约定口径再重跑。
* **「C# 快是因为结构共享」**：这条在结构上有独立证据（`GetAvailableDecisions` 的 LINQ 投影、
  每决策分配 298.6 KB），可以保留 —— 但那是**分配量**的证据，不是**吞吐**的证据。

## 二点五、测试迁移（全工程最大的单项，单独展开）

### 先把靶子摆正：要搬的是 **1013 条，不是 3502 条**

3502 是**运行时**断言数；可搬运的单位是**静态 `check()` 站点**，共 3023 个，按子系统分：

| 子系统 | 站点 | 去向 |
|---|---|---|
| **core 规则** | **1013（33.5%）** | **← 只有这一坨要搬到 C#** |
| ui | 1330（44.0%） | **留 Godot** —— 决策 9 之后 UI 只剩排版，反而更该留 |
| net | 213（7.0%） | 改服务端权威 = **重写**，不是迁移 |
| guide | 144（4.8%） | 决策 10，排最后 |
| persist | 120（4.0%） | 存档/回放判死 ⇒ **重写** |
| ai | 84（2.8%） | 决策 7，随 AI 重写 |
| patch | 70（2.3%） | 热更是 Godot 侧机制，**留** |
| 未归属 | 49（1.6%） | 逐条看 |

那 1013 条再分三档：**纯查询/常量表 172 条**（17%）、
**装载盘面 → 做一次变更 → 比状态 716 条**（71%，大头）、**要驱动决策循环或整局 125 条**（12%）。

### 三条路：不是三选一

* **(a) 逐条人工翻译成 xUnit —— 不做，只当对照项。**
  1013 条 × 队友自己的测试密度 = **7000~14000 行新 C# 测试码**（是 C# 内核本体的 1.4~2.7 倍），
  **40~70 人天**。而且其中 **389 条（38%）在 C# 造出 `events`/`mods` 容器之前根本写不出来**。
  只有约 30~60 条零散条目值得手翻。
* **(b) 数据化 + 两边各一个 runner —— 主路**，且与对拍 L0 合并成一件事。
  **machinery 成本 14~24 人天**（我们 11~18、队友 3~6，可并行），**不含 triage**。
* **(c) 只靠对拍不迁移 —— 不能单独成立，但留着当发版前的端到端闸。**
  证伪证据（对拍规格自己量的）：2 人局 40 步的随机轨迹，9 类询问只走到 2 类，
  七类一次没碰到；而 `block9_three_cells` 在人数系数 k **完全缺失**时照样 PASS。

### 合并前要先认两个缺口

1. **`expect` 只有两类不够。** 现在只支持标量与向量，而 1013 条按形状分：
   `== 整数字面量` 只占 19%，`== 表达式` 26%、`and/or 复合布尔` 24%、裸布尔 18%
   ⇒ **照现在的 schema，L0 只吃得下约五分之一**。必须加第三类：**canon 子集逐字段比**
   （这同时就是 L1 canon 的复用）。
2. **loader 只走完三分之一。** 现有 `CellFields` 只有 11 个键，而 `make_cell` 有 30 键；
   tune 旋钮（19 个 core 测试、66 处）与 events 容器（14 个测试）**完全没有**。

### 关键一招：**GD 侧录制代理**

给 `CWWorld` / `CWActions` / `CWCardFx` 做同签名的代理对象，逐调用落
`(pre-canon, op, args, post-canon)`。
**这一件把那 716 条「装载盘面→变更→比状态」从「手翻」变成「跑一遍收割」** —— 3~5 人天。

### 每批三道闸，一条都不能省

| 闸 | 判据 | 为什么 |
|---|---|---|
| **一 · 双跑同一份数据** | 同一份 JSON，**GD runner 与 C# runner 都要绿** | GD 绿 = 用例忠实于原断言；C# 绿 = 真的等价。**只做 C# 那一半就是把靶画在自己身上** |
| **二 · round-trip 自检** | 世界 → JSON → 重新装载 → 再跑探针，逐位相同才许落盘 | 已经抓到过 `effector_round` 这种「只进世界不进文件」的字段 |
| **三 · 原测试不删** | GD 的 `check()` 留到 GDScript 内核退役；CI 加「已迁移条目数单调不减」 | —— |
| 四 · 变异检验（建议） | 随机把 C# 规则常量 ±1 或反转一个分支，**抓不到红就说明这批搬的是空气** | —— |

## 三、不可逆的地方（复核补的，七路都没写）

**⚠ 最要紧的一条：真正不可逆的那一步和直觉相反。**

服务器换版是 `DRAIN` 排空式热切，旧 `game/` 还留着 ⇒ **服务器侧可以回滚**。
不可逆的是**全量客户端**：Release 一旦发出并被玩家装上，`boot.gd` 的 `decide()` **没有降级档**
（`build <= installed` skip / `build <= base` skip / `build == blocked` skip，没有任何往回走的路）。

⇒ 正确顺序是 **「新客户端先挂 Release 并给足下载窗口 → 再切服务器 → 旧服务器目录保留 N 天」**，
而不是平时那条「补丁先、服务器后」。**这一条要写进发布纪律。**

### 四条必须立成硬不变量

1. **`boot.gd` 与 `patch_state.gd` 永远不得依赖 sidecar / C# 内核。**
   `patch_state.gd` 文件头本来就写着它「故意不引用任何游戏里的东西……副作用是它自己永远打不了补丁
   —— 这是好事：坏补丁不该有机会关掉自己的回滚」。换内核后这条从隐性变成必须显式验收。
2. **sidecar 启动失败绝对不能计进 `STRIKES`。**
   `patch_state.gd:82` 的 `STRIKES := 5` 是**永久本地拉黑**，只有全量发版能解。
   杀软误杀 exe、SmartScreen 拦截、Mac 上压根没有 sidecar —— 任何一条被当成「补丁坏了」，
   五次之后那台机器就被**永久锁在旧版**，而这是服务端看不见也改不了的状态。
3. **握手的 `ruleset` 闸不能校验规则 build。**
   同一份 `CellWar.Core.dll` 要走「补丁 → 客户端」和「deploy → 服务器」两条路，
   而纪律是补丁先、服务器后 ⇒ **必然存在客户端规则版本 ≠ 服务器版本的窗口**。
   联机是服务端权威所以算不错，但若加了 ruleset 闸，这个窗口里**所有已打补丁的玩家会被踢出联机**。
   ⇒ ruleset 闸只校验宿主 ABI，不校验规则 build。
4. **握手被踢的提示要带下载地址。**
   `cw_net.gd` 的 `ERRORS["version"]` 现在只说「请更新游戏」。
   决策 2 的全员重装就靠这一行字（`boot.gd` 的 `too_old` 分支已经有一句带地址的人话，抄过来）。

### 三件玩家可见的损失，要 Kevin 定怎么交代

* **老存档与老回放全部作废**，且不可逆：`cw_save.gd:17` 的进行中单机存档、
  服务器上的回放归档（`cw_room.gd` 开着 `record_replay`，玩家可下载）。
* **mac 玩家在换内核那天失去离线单机、热座、教程、回放**
  （sidecar 那一路的推荐是「第一版 mac 先不带 sidecar」）。
* **网页版单机的 AI 跑在服务器上** —— 每个网页单机人机局都在服务器上占一份 C# AI 算力。
  这笔账拍板记录 §三·新二只算了联机那份。

## 四、规则缺口清单（对拍与补齐的输入）

复核独立复算确认的几条硬结论：

| 缺口 | 证据 |
|---|---|
| **卡牌只缺 1 张**：【癌症转移】 | PRD 68 卡名 / 83 条卡池条目；C# 67 / 82，唯一差集。其余 66 张权重向量逐个相等 |
| **唯一权重失配**：【糖酵解爆发】 | PRD 2/3/4 ↔ `Cards.cs:111` `[3,4,6]` |
| **9 张卡「单位错位」** | C# 能量是十分位整数，但这 9 张把「1 能量」写成 `1`（= 0.1），**只有应有效果的 1/10**。改完强度 ×10 —— **这是平衡级改动，不是修字** |

## 五、一条结构性事实：L2「同种子整局对拍」不可能成立

**两边的随机数发生器本身就是两个不同算法** ——
我们走 `RandomNumberGenerator`（Godot 内建 PCG），C# 走 `IDeterministicRng.cs:62` 的 `Xoshiro256StarStar`。

⇒ 即使把抽法口径全部对齐（`NextInt(6)` → 1..6、`NextDouble` → 整数千分位），
**同一颗种子也永远出不了同一条流**。

对拍规格自己做对了（L1 用「一方录、一方念」的教师强制重放，不靠同种子），
但七路里没有一路把这条前提讲明 —— 而有一路关于「守住 `_playout_seed` 逐位一致就能不重标定」的
整段论证，正好压在这个不成立的假设上。**那段要作废。**
