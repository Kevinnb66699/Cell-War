### 2.6 `flow[]` 的九个动词

每条通用字段：`do`（必填）、`step`（Step 标签）、`prd`（**PRD 行号，对账闸用**）。

| `do` | 字段 | 语义 | 阻塞？ |
|---|---|---|---|
| `state` | `load` `ui` `reveal` `npc` | 结算界面 + 状态。**PRD:39 ⇒ `flow[0]` 必须是它且必须带 `load`**（校验器硬核；**唯一例外是间章：`load` 可以显式写 `null` 承接上一关的活局面**，§2.5）。**`load` 有两种写法**（S5 修订，2026-09-19）：① 字符串 = 点名一份 world；② `{"by_player_type": {"BCell": "b", "TCell": "t", …}}` = **按玩家此刻的免疫种类**挑一份 ——键就是 world spec 里 `cells[].type` 那个词，导演运行期照镜像里玩家那只现挑（`cw_tutor_director._world_for`），`flow[0]` 只许写法 ①（「重置本关」退回的就是它）；③ `{"recenter": "player", "radius": 11}` = **不点名任何一份 world**，把**活局面**`dump_world` 出来、每个坐标键平移 −P（P = 锚点那只此刻那格 ⇒ 它落到 `(0,0)`）、半径改成这里写的那个数，再走**关内换盘**（间章分镜 2，S9a；平移本体在 `CWTutorScript.translate`，全案唯一一处）。②③ **互斥**，且都只许出现在关内的 `state` 上 | 否 |
| `say` | `who` `lines` `beats` `auto` | `who`：`player`（默认，PRD:23）/ `seat:<n>`（PRD:407）/ `narrator`（PRD:397 的「……」）/ `ui:<控件 id>`（PRD:447、PRD:479 按钮弹提示） | 是 |
| `point` | `ui` `hex` `mode` `tip` | UI 提示。`ui`：`["bar:迁移","panel:end","panel:level","hand","skill:转移"]`；**`mode`：`soft`（默认，PRD:49 轻微慢闪）/ `arrow` / `fullscreen`（PRD:445 全屏引导指向）**；`tip` 挂在目标上的一句话（PRD:447） | 否 |
| `unlock` | `ids` | 图鉴解锁（PRD:29 的 12 处） | 否 |
| `play` | `fx` `at` `secs` `args` `seed` `await` | 教程演出层的一段（`cw_tutor_fx` 的一支）。**S9b 已接线**：导演发一条 `want_play(fx, args, done)`（同 `want_npc` 的形制），`CWMatch` 喂给挂在棋盘底下的演出库；`at` / `args.actor` 里的 `"player"` / `"seat:<n>"` 由导演翻成席位号（演出层再用注入的 `seat_at` 换成格）、`"q,r"` 翻成 `Vector2i`；`await: true` 等回执才翻页、`false` 只等 `secs`，回执带**段号**（上一段的迟到回执解不开这一段）；`args.actor` 那一席的**真身由 `CWMatch._sync_cells` 让位**（演出层自己 `_hide` 藏不住，每帧会被重写），贴图 `args.tex` 也由它现补 | 是 |
| `wait` | `secs` | 「等待几秒」（PRD:395） | 是 |
| `player` | `allow` `until` `hint` `hex` `ui` `reset_when` `advise_when` `advise` | 【O-玩家】：开闸 + 完成判据 | 是 |
| `npc` | `seat` `plan` | 给某席换脚本（`Decider.plan`，`cw_tutorial_npc.gd:147`） | 否 |
| `hook` | `call` `args` | 交给关卡脚本的一段（§3.7） | 是 |

**只有九个动词，不允许第十个**（甲的纪律照搬）：新需求先问「能不能写成 `play` 的一支 fx」，再问「能不能进钩子」。
连续的不阻塞条目同帧跑完 ⇒ `state → point → unlock → say` 对玩家就是「界面换好了、格子亮了、书解锁了、然后角色开口」，正是 PRD:39 的次序。

## 3. 流程机（导演）语义

### 3.1 推进

导演持一个游标 `_at`（flow 下标）。驱动只有三个源：

1. **`queue.on_step` 的 `step_end`**：装闸 / 判上一条 / 翻页的**正牌时机**。
2. **每帧 `_process`**：镜像谓词（`until` / `reset_when` / `advise_when`）、`say` 的节拍、`wait` 的计时、`play` 的 `apply(t)`、`hook.resume()`。
3. **玩家点「继续」**：皮发 `advance_pressed`（只有 `say` 且 `auto:false` 时导演才理）。

`_apply(at)` **幂等**：同一条被装两次不会出第二份效果。

**装闸的唯一正确时机是 `step_end`**：`cw_kernel_inproc.gd` 的 `_on_ask` decider 路是 `_close_step()`（推 step_end + sync）→ `await deciders[pid].ask(req)` → `_open_step()`（推 step_begin）。所以 **`step_begin` 标的是「这一问已经答了、动作开始演」**，不是「要问了」。
⚠ **行号存疑**：丙给 `:391/393/395/399`，甲与乙给 `:399/400-401/406`。**第一片开工第一件事按文件核一次**，把准确行号写进新文件注释。
**关首再装一次**（`open()` 返回后、`kernel.run()` 之前）：关的第一帧在队列泵到那条 `step_end` 之前就画出来了，不提前装玩家会先看见一瞬间的全套界面（`match.gd:532` 的注释原账）。

### 3.3 完成判据 `until`：三类谓词

老 `guide_watch.gd` 的 `KEYS` 表作废，但**两条教训原样照抄**：

> 评委 2 的开工前提第 1 条：「`ctx` 九个方法一条签名都没给，而护栏 `t_tutor_hooks` 的判据就是『`ctx.` 后面只许是那九个』—— 九个是哪九个没定义，这条闸写不出来。」本节把它定死。

```gdscript
## game/scripts/tutor/cw_tutor_ctx.gd —— 钩子 → 导演 的唯一接口。
## 纪律：ctx 不暴露 kernel / mirror / game / view / stage 任何原始句柄；钩子文件零成员变量。
## 每个 await 原语返回前都过一次代际闸（见下 alive()）。

## ① 跑一条声明式条目 —— 与 flow[] 完全同构的九个动词（say / point / unlock / play / wait /
##    player / npc / state / hook）。钩子不自己说话、不自己画，一切经这里回到导演。
func beat(row: Dictionary) -> void            ## 协程

## ② 等一个谓词（§3.3 的三类，同一张表、同一个基线）。timeout_secs > 0 时超时返回 false。
func until(pred: Dictionary, timeout_secs := 0.0) -> bool    ## 协程

## ③ 只读查询（白名单，返回派生量的副本，绝不返回镜像本身）：
##    "cells" -> [{seat, at:Vector2i, type, alive, energy}]        "tile" (arg: Vector2i) -> {state, type, solid}
##    "dist"  (arg: [a, b]) -> int                                  "beside" (arg: [seatA, seatB]) -> bool
##    "alive_count" (arg: "immune"|"cancer") -> int                 "round" -> int
##    "energy" (arg: seat) -> int                                   "active" -> [Vector2i]
func read(q: String, arg = null) -> Variant

## ④ 代际闸：这一代还活着吗（重置 / 目录跳关 / 换局后为 false）。
##    **护栏硬要求：钩子里每个 while 的条件都必须含 ctx.alive()**
func alive() -> bool

## ⑤ 让一帧（内含代际闸）
func frame() -> void                          ## 协程

## ⑥ 钩子自己的演出随机数（种子来自数据；**绝不碰内核 rng**）
##    【实测改判 S8】种子具体从哪读：`hook.args.seed`；没写就按**关 id** 定死（`hash(level.id)`）。
func rng() -> RandomNumberGenerator

## ⑦ 钩子唯一合法的状态落点（钩子文件不许有成员变量；重置时随代际一起清空）
func state() -> Dictionary

## ⑧ 记一笔（进无头流水账与开发日志，不上屏）
func log(msg: String) -> void

## ⑨ 剧本写不下去了：warning + 挂起（不静默继续、不替玩家乱答），出路是常驻「重置 / 目录」
##    【实测改判 S8】**钩子里必须写 `await ctx.fail(...)`**：不等它挂住，钩子自己就返回了，
##    主游标会把 `hook` 那一条翻过去 —— 恰好是“静默继续”那一种死法
func fail(why: String) -> void
```

**取消语义（搬乙的 epoch，`match.gd:583/1099/1174` 有先例）**：

```gdscript
## cw_tutor_director.gd
signal dead            ## 永不 emit
var epoch := 0
func invalidate() -> void: epoch += 1      ## 重置 / 目录跳关 / 换局各调一次
## 【实测改判 S8】换局走的就是 `director.open()` —— 它的第一行就是 `invalidate()`，
## 否则上一关挂着的钩子协程会在新关里接着跑。`invalidate()` 顺手清 `ctx.state()`

## cw_tutor_ctx.gd —— 每个 await 原语的结尾统一一句
func _gate() -> void:
    if _ep != director.epoch:
        await director.dead                ## 旧协程停在这里，随导演一起被回收
```
GDScript 的协程不能被杀，只能让它永挂。**风险与对策**：挂死的协程持 ctx / 导演引用 ⇒ ① 导演每关一只、关末显式 `dispose()`（**【实测改判 S8】这一条不成立** —— Godot 4.5 上 `queue_free()` 导演**并不能**把挂死的协程回收干净：20 代约 280 只对象，free 之后只掉 39 只）；② `t_tutor_hooks` 的对象账改成**两轮 churn 对比**：钩子分别跑 3 帧与 12 帧、各做 20 次重置，**两轮涨幅必须一样大**（实测 281 vs 280，约 14 只/代）—— 要钉的性质是「挂死的是**每代一只**、与钩子跑多久无关」，原来那句「不单调上涨」写不出真判别力；推论：**钩子里的 await 原语越少越省**（S10/S11 照这一条）；③ **每个 `while` 条件含 `ctx.alive()`** 的源码闸，让钩子自己从循环里退出来，把「永挂」压到最少的那几个 `await` 上。
（乙的原风险是「挂的是整关主协程」；本稿只有第七关与间章两个钩子会挂，且都被 `ctx.alive()` 的循环闸提前收口 —— 比乙的面小一个量级。）
