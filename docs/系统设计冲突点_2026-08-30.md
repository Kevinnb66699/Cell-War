## 冲突 1：修饰排序 —— 语义阶段 vs 打出先后（骨架级）

### 对方的要求

费用文档 §四把修饰排进 **11 个语义阶段**（行动合法性 → 基础费用 → **基础值替换**
→ 固定加费 → **固定减费** → 倍增 → 倍减 → 普通上下限 → **免费豁免** → 行动硬下限
→ 不可豁免附加费），§六 明写：

> 「角色被动 → 卡牌 → 技能 → 世界事件」可作为同阶段内的稳定排序，
> 但不能取代上节的语义阶段。

攻击文档 §5.3 是同一套：`语义阶段 > 显式优先级 > 来源顺序 > applied_seq > 稳定 ID`。

### 与现行口径的冲突

**口径 #73（2026-08-30 团队定案）**规定的是：① 基准值 → ② **卡牌按打出/装备的先后
逐张结算** → ③ 世界事件最后。两者对同一局面算出不同结果：

```
基准 1.0，先打【CXCR3趋化】(-0.5)，再打【炎症趋化】(改为 0.5)

  口径 #73（现行）    1.0 → 0.5 → 被改写回 0.5  = 0.5
  新设计（语义阶段）  替换(阶段3)先于减费(阶段5)：
                     1.0 → 改为 0.5 → -0.5      = 0.2
```

### 更要紧的：**定案 A 会整个失效**

定案 A（同日）保留了【炎症趋化】的「抬价」，理由是「这属于打出顺序的博弈」，
并因此把卡面从「降为 0.5」改成「**改为** 0.5」。

但在新设计下，**免费豁免是阶段 9，排在基础值替换阶段 3 之后**——
【组织巡航】的免费永远盖过【炎症趋化】的改写，抬价场景**不复存在**。
那么「改为」与「降为」也就不必再区分，定案 A 的改字理由随之消失。

### 要裁什么

**二选一，不能并存**：

- **甲**：维持口径 #73（打出先后），新设计的 §四/§六 按此改写，语义阶段降级为
  「同一时刻多个效果的平局规则」。定案 A 保留。
- **乙**：改用语义阶段，**口径 #73 作废、定案 A 作废**，PRD 措辞草稿 〇.3 整段重写，
  【炎症趋化】的卡面改字取消。

⚠ 这条决定后面所有代码的骨架，**必须最先裁**。

**我的意见**：语义阶段在数学上更严谨（防止「减免跑到倍增之前」这类错误），
但口径 #73 是团队三天前刚定的、已实装并写进 PRD 草稿。建议**让提设计的队友先说明
为什么要推翻 #73**——如果只是「更规范」，代价是推翻一条已落地的团队定案。

## 冲突 2：一次性修饰的默认消耗策略

### 对方的要求

费用 §七.3：

> `ON_BENEFIT` 实际降低了费用才消耗（**默认推荐**）

攻击 §5.4：

> 【标记】、【囊性护甲】这类默认采 `ON_BENEFIT`：**实际改变了预定伤害才消耗**

攻击 §6.3 更直白：「**0 点事件不能骗掉护甲**」。

### 与现行口径的冲突

**这正是我 2026-08-30 提的甲案，而 Kevin 选了乙案。** 两处都撞：

**（a）费用侧** —— 定案 D 乙案定的是「**免费额度省，限次折扣不省**」：限次折扣
（CXCR3趋化 / LFA-1黏附 / 炎症趋化 / 上皮—间质转化）只要适用就扣次数，
哪怕一分钱没减到。文档的 ON_BENEFIT 默认与之相反。

**（b）伤害侧** —— 冲突更硬。实测：

```
细胞膜修复(-1.5) + I型干扰素(-1.0) 挡 0.5 的【微环境压迫】

  实际损失              0.0
  细胞膜修复被消耗       是
  I型干扰素也被消耗      是      ← 文档要求保留
```

这正是**定案 #57**（同一次损失把同名护盾全用掉）与 Kevin 原话
「**这本身就是一种战术，不给例外**」要的效果。

**定案 B** 也撞：【囊性护甲】现在在 `cancer_hit` 顶部无条件取用，
0 伤害照样占额度——文档 §6.3 明确不允许。

### 要裁什么

伤害侧与费用侧可以分开裁，但**建议保持同一直觉**，否则玩家要记两套相反的规则：

| | 现行 | 文档 |
|---|---|---|
| 费用侧限次折扣 | 照扣（定案 D 乙案） | 不扣（ON_BENEFIT） |
| 伤害侧护盾 | 全消耗（定案 #57「战术」） | 只在起作用时消耗 |

**我的意见**：伤害侧的「战术」裁定是 Kevin 明确表态过的，不建议翻案；
费用侧刚拍完乙案，也不建议隔天再翻。倾向**维持现状，把文档的默认改成 `ON_COMMIT`**，
把 `ON_BENEFIT` 留给将来卡面明写「仅在生效时消耗」的新卡。

## 冲突 3：免费额度的竞争规则

### 对方的要求

费用 §九：两个免费额度进同一竞争组，一次移动最多消耗一个，**向健康组织迁移时
【组织驻留】条件更窄、优先豁免，【组织巡航】保留**。

### 实测现状

```
先装巡航后装驻留 → 消耗了 巡航
先装驻留后装巡航 → 消耗了 驻留
文档要求            始终是 驻留
```

现状按 `equip_seq`（装备先后）排队，谁先把费用变 0 谁被消耗；
文档要按 specificity（适用范围窄者优先）排。

**「一次移动最多消耗一个免费额度」这一条现状已经满足**（定案 D 乙案），
分歧只在**选谁**。

### 附带：这条依赖改字

文档 §九.2 自己也写了，这一裁定要求卡面从「每行动回合**首次**」改成
「每行动回合**一次**」，否则按字面两个效果在首次健康迁移时都已到触发时点。
**这是一条新的「待队友改字」项**，要并进 `PRD差异对照.md` 的 〇 节。

### 要裁什么

免费额度的竞争按 **specificity** 还是按 **打出/装备先后**？
——本质上是冲突 1 的一个具体切面，**跟着冲突 1 一起裁**。

## 冲突 4：`LethalEvent` 与口径 #68（低，可兼容）

攻击 §5.6：

> 「直接消灭」不应由业务代码随手调 `kill()`，而应建立 `LethalEvent`，
> 显式标记是否可被 BCL-2 或其他死亡替代阻止。

**口径 #68** 定的是：【吞噬体成熟】的处决不是能量损失，**BCL-2 救不回**
（先免死再被处决的顺序按字面走）。

**这两条不冲突**——只要 `LethalEvent` 的「可否被阻止」标记按口径 #68 设成
**不可阻止**即可。但默认值必须选对：如果实现时图省事让 BCL-2 默认能拦，
口径 #68 会被静默改掉，而且不会有任何测试报错（现有断言只测了处决本身）。
**实现时要显式写死并补一条断言。**

## 附一：文档抓到了一个审查漏掉的真问题（👍）

攻击文档 §6.1 要求巨噬【吞噬】的恢复量「根据目标的**实际能量损失**计算，
不根据理论伤害」。**现状确实是按理论伤害算的**，实测：

```
目标结算前只剩 0.5 能量，被巨噬大成功 2.0 ×2(标记) 命中
  理论伤害 dmg          4.0
  目标实际失去           0.5
  巨噬恢复了             2.0     ← 按 ⌈4.0÷2⌉
  按实际损失应恢复        1.0     ← ⌈0.5÷2⌉
```

PRD 原文是「恢复 ⌈**受击方损失能量** ÷ 2⌉」——「损失」显然指实际失去的量，
所以**现状是个真 bug，白多回 1.0**。残血目标越多、这个偏差越大。

同一根因还影响所有「造成 X 伤害后」类效果：现在读的是 `dmg`（理论值），
文档要求读 `DamageResult.actual`。这条是采纳文档的**净收益**，
与三处冲突无关，**可以独立先修**。

（这一条 2026-08-30 的全量审查没抓到——我当时核对的是管线顺序与消耗时机，
没有核对「返回值代表理论伤害还是实际伤害」。记在这里当作审查盲区的样本。）

## 附二：文档对现状的两处描述出入（供队友更新文档）

**① 费用 §一** 描述的「两套逻辑」已于 `317eb5a` 合并为
`_move_cost_chain(cell, dest, base, commit)`，`commit=false` 报价、`commit=true` 兑现。
文档列的四个结构性问题里，前两个（UI/AI/执行价格不一致、报价误烧修饰）已消除。

**② 攻击 §6.4** 说 T 细胞【细胞毒性增强】的无视减伤部分「直接扣能量」，
言下之意绕过了死亡检查。**实际没有**：现有代码扣完能量后调 `game._after_damage()`，
BCL-2 免死与死亡判定都走到了，也有日志。文档要改的是**统计与标签的一致性**，
不是修 bug——这一点值得在文档里说准，免得实现时以为在修一个不存在的缺陷。
